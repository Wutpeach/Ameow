# Ameow 体验与原生验收

准备用户试用、核查 UI/文案/动效、或解释实际证据时读取。共享 Ship 负责通用产品验收与协作方式；此处维护 Ameow 的使用入口、平台方式和证据边界。

## 交给第一位实际使用者

用户是 Ameow 的第一位实际使用者。更新日志、重要使用/安装/升级文档，以及影响用户体验的功能，由用户最终审阅和验收。执行方先核事实、做必要自检，及时交付一组稳定可用的改动、准确入口和简短验收要点；布局、文案理解、动效与操作手感不靠不断扩展自动测试代替本人判断。不逐句或逐次中间修改打断用户，已明确接受的同版内容不重复要求批准。

本人默认在根 main、共享 target 验收。按 [development.md](development.md) 准备匹配的主线与配套，再提供 Windows 启动命令或 Mac 固定开发 App。记录实际运行来源和覆盖，源码手验可证明相应功能，不能冒称已运行正式包。发行资产仅按实际安装/发布需要准备，流程见 [release.md](release.md)。

日常只验受影响流程并复用仍适用的证据。每版发行前两平台最小回归为启动、粘贴、普通下载、取消、扩展连接和退出，按本版改动追加必要流程，不追加无关全产品矩阵。记录实际源码、exe/App 身份和哈希、方法、结果、失败前驱与未测限制。真实故障先修，环境受限或待人工逐项列出，未知不能算 PASS。完整检查集中在用户准备发 Tag 后、实际打 Tag 前，不把每次体验修订变成全量验证。

## 平台原生交互

Mac 通过 Mac 本机 Cindy 的 computer use 验证真实粘贴/焦点、Full ↔ Compact、后台与菜单栏交互。先发现当前目标电脑的实际能力，分别核对 Cindy 工具、driver 权限、SSH 进程权限及锁屏状态。SSH 的 AX=false 不能证明 Cindy/driver 无权限；不以 shell 模拟键鼠替代真实输入。锁屏或权限阻塞时写明具体缺项和恢复条件。Mac 实测系统范围沿用 CONTRIBUTING，不扩张为所有支持版本通过。

Windows 按用户选择使用自动检查加本人手验，不打开 computer use。两平台的自动、原生、本人验收各保留实际覆盖范围，不互相充当通过证明。

预览合成状态只证明隔离展示；截图裁到可审查的窗口或元素，动效需连续渲染证据。真实设置、下载和系统交互只在已选择且获授权的实例/数据范围验证，保全日常配置与既有资产。

## 证据与结论

验收记录保留用户所审稿件/运行版本、实际资产用途与反馈。用户通过应有原话或 Cindy 原生会话出处；伙伴核事实、CI 成功、合法哈希或只读工具 PASS 各只证明其实际范围。需要汇总源码或发行就绪情况时再读 [evidence.md](evidence.md)，不要求每个日常修复建立整套发行证据。

更新验证写明实际运行的旧生产版本、EXE/App 身份、目标 feed 和已观察阶段。旧公钥静态验签、当前源码 fixture 和新版 NoUpdate 不能证明旧生产消费者的 Available / Ready / 安装 / 重启。仅在可靠隔离入口运行有界旧版检查；没有入口时保留未知，不触碰用户实例或重建伪旧客户端来补证。
