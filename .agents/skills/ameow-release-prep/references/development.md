# Ameow 执行

接手仓库研究、实现或修复时读取。先读根 AGENTS、[CONTRIBUTING](../../../../CONTRIBUTING.md) 和相关差异；文件与内容搜索使用项目的 fff 工具。按本次行为读取相关 OpenSpec 能力，不把全部规范作为每次任务的前置。需求变化使用项目现有 OpenSpec Skills；符合现有规范的实现修复不另造空洞 change。协作派发、授权边界和回传方式沿用共享 Ship。

## 上下文与工具

伙伴会话的记忆和工具偏好不视为已自动读入。先从交接取得影响本轮的决定和必要记录，有缺项再定向读 Cindy 原生来源历史。GitHub 优先发现用户现有的 Magpie GitHub MCP；Cindy 插件为空不能证明该 MCP 不可用。操作能力确实缺失时再使用已核同账号的 gh，不为此安装另一套连接器。现有打包/CI 脚本需要 gh 时继续沿用。

Cindy 的项目记忆按实际工作目录归属，可能存于宿主管理目录；仓库没有 `.cindy/memory` 不代表没有项目记忆。同一工作目录的任务共享项目记忆，伙伴另有记忆范围，具体路径按宿主和交接核实；不将单个会话上下文当共享记忆，也不默认同步整份伙伴记录。长期记忆走当前宿主的实际记忆能力，不另造 journal 或记忆层。

### 当前改动的验证

日常按风险只做必要局部检查，需要实际运行时才增量 build；功能/性能修复保留少量能证明正确与收益的定向检查。围绕稳定功能块集中验证，不随每次修改全量编译、跑整套测试或 CI。纯文案、流程和 Skill 修订不触发产品构建、制包或全量测试。

延迟、卡顿问题先用少量分段测量梳理从用户操作到结果的等待链，再按已授权目标一起评估前台等待与后台排队、重复本地工作。最小实验用于确定足以解决本轮问题的范围；首个局部改善不自动成为交付停点。收益与仍未知的环节分别说明。

本人的功能验收默认使用已同步远端的根 main 和共享 target。先准备好匹配的源码、版本、中英文档、CLI/host 和真实扩展 dist，再给启动入口：Windows 使用 cargo run --locked；Mac 按系统原生机制复用固定 main 开发 App。不为验收另造 ZIP、专用包或入口；实际安装/打包需要时再读 [release.md](release.md)。未经本轮授权不自行同步、提交或推送。

本地重任务遵循 CONTRIBUTING：每台电脑串行、Cargo 四 jobs、仅构建进程低优先级；应用和长期预览按正常优先级单独启动。已有执行文件、用户数据、缓存与证据按实际保留授权处理。

使用共享 target 切换工作树、features 或运行用途（预览、测试夹具、正常应用）时，先核实际编译输入、构建模式和 EXE/测试 runner 来源，再复用结果；身份不符时只重编受影响目标。

涉及界面时先读 DESIGN.md 和现有设计参考，实际值查其关联 Rust 源码。更新设计 token 时同步 `.impeccable/design.json`；后来明确的用户决定优先于历史示例。视觉/交互验收见 [acceptance.md](acceptance.md)，面向用户的说明见 [documentation.md](documentation.md)。

临时证据放现有任务交接目录或项目约定的忽略目录；docs 只放持续维护的工程指南。阶段成果回来源会话，GitHub 任务记录由已获授权的负责者维护。

交付后按 Ship 收尾约定核对运行依赖，在已有清理授权内回收结束测试的重复程序、隔离 runtime、下载包副本和生成依赖；保护最终正式资产、必要小回执、原始媒体及未提交源码/补丁，签发资料沿原保管约定保留。共享 target 和仍在用的素材按实际依赖保留；清理回报区分逻辑大小、硬链接/回收站与实际磁盘空间变化。
