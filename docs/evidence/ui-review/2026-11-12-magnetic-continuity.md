# 磁吸与展开、收起的连续性修复

日期：2026-11-12。用户重新体验到展开、磁吸和收起的顿感，授权优化这些衔接，并指定官方 Magnetic Nested 为参考。此前 2026-11-09 对照中已经记录收起初始偏移硬清零；本轮获得新的修复授权。当前实现未提交、未推送，实际手感待用户验收。

## 参考与原因

- 官方页面：https://motion-primitives.com/docs/magnetic 。已读取官方 Nested 示例和核心实现；GitHub 读取时的提交为 `120f64f6ca60348e251f929e9c81f11ccbe45eda`。其目标回零仍经过同一条 spring，不直接清空当前位移。Ameow 继续采用单个整体对象，不新增内部文字位移层。
- `magnetic_spring::Hover::sample` 之前把 `full_intent=false` 直接当成关闭全部磁吸的条件，即使窗口仍完整展开也立即清空位移与速度。旧记录已测到约 5.709px 的初始跳变，见 `docs/evidence/issue32/magnetic-nested-stage-report.md`。
- 本轮短时原生运行另测到应用 Render 间隔中位数 34.4825ms。所用 GPUI 0.3.11 的 `WindowOptions::inactive_frame_interval` 默认是 33,333us；主悬浮窗通常不获取焦点，因此会进入该限制。该数据是应用绘制采样，不是 GPU Present 帧率。

## 修改

- 收起开始时，只把磁吸目标设为零，保留当前弹簧位置与速度；继续由已有 fullness 渐变淡出。仅在该位移已不可见后清理弹簧。中途重新展开时，从当前状态承接；收起期间不再追逐仍在窗口内的鼠标。
- 保留默认 Converged 展开/收起曲线、展开末段渐入、6px 幅度、共同平移、原生边界和既有低动态效果处理。关闭磁吸或开启减少动态效果仍立即清理残留。
- 仅在主悬浮窗设置 `inactive_frame_interval: None`，使用 GPUI 正常调度，继续保留电源和温控的默认节流。原来的按需帧请求继续负责停止静止后的动画。设置和 Gallery 窗口的参数不变。
- 曾试验将非激活间隔固定为 16,667us，在本机采样中位数为 20.631ms；最终采用 GPUI 的正常调度，不固化这个额外帧率上限。各次原始记录均保留在下述证据目录。
- 没有增加或移除 UI 状态。现有 Gallery 场景继续适用，113 项目录未变化；Gallery 会固定所选 Compact/Full 外观，实际移入、移出衔接需在普通悬浮窗口验收。

## 集中验证

- `cargo test --locked --bin ameow --quiet`：167 通过、0 失败、2 忽略。新增回归覆盖收起切换位置/速度连续、快速移回，以及 4/16/33ms 采样间隔下与真实窗口运动模型的组合。既有展开渐入、6px 上限、减少动态效果和禁用处理仍通过。
- 将相同新增回归放到修改前的磁吸实现运行，按预期失败：实际偏移直接成为 `[0, 0]`，应保留的位置为 `[1.8041583, 0]`。这证明该回归能抓到原缺陷。
- 最终 `cargo build --locked --bin ameow` 与相关文件 `git diff --check` 通过。
- 最终 EXE 的短时原生 fixture 实际执行两次收起与重新展开，退出码 0；814 个应用 Render 样本，432 个中间 fullness 样本，间隔中位数 6.3ms、P95 7.329ms。与前述 34.4825ms 的同类周期探针比较，仅能说明取消非激活节流后的应用绘制间隔缩短，不能换算为显示器实际帧率或保证主观顺滑度。
- 最终 EXE 的独立静止检查退出码 0；900–1450ms 区间没有 Render 样本，未形成持续重绘。两项运行的前台 HWND 均保持原值，没有注入鼠标或键盘输入。
- 最终 EXE 无窗口读取的 113 个场景与 JSON 一致。
