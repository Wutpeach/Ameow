# Popup 预览工作台

从仓库根目录启动：

    npm --prefix browser-extension run preview

打开 http://127.0.0.1:4322/ 。首次使用先安装扩展开发依赖：

    npm ci --prefix browser-extension

端口被占用时可以复用正在运行的服务，或指定另一个端口：

    npm --prefix browser-extension run preview -- --port 4323

前台运行时按 Ctrl+C 停止。重启电脑后再次运行启动命令即可。

## 使用

- 左侧选择未授权、已同步、同步中、空会话、失败或连接异常等场景。
- 上方切换浅深主题、中英文、示例站点与页面工具偏好。
- Popup 内可体验授权、同步、站点菜单移除、提示浮层及诊断复制；重置按钮恢复当前场景。
- 修改产品源码后点击“重新载入最新源码”。刷新后继续使用当前场景选择，源码身份记录在页尾。

预览直接读取上一级的 popup.html、popup.css 和 src/popup.mjs，通过现有
esbuild 在内存构建，不维护另一份界面副本，也不写 dist 或产品配置。
根目录、资源和依赖按工具所在位置解析，不依赖本机绝对路径或当前工作目录。

尺寸从 Popup 实际渲染中测量，没有缩放变换。预览窗口遵循 Chromium
25×25 到 800×600 CSS px 的范围；超高时在内部滚动，超宽时标出溢出。
浏览器缩放保持100%，可以按原始CSS尺寸比较排版与点击范围。

## 状态与边界

scenarios.js 保存场景目录和示例站点，fixture.js 只替换当前页面的 Chrome API
边界响应。产品自己的渲染和事件处理决定文字、按钮、开关及错误恢复。
授权/同步/移除模拟成功回执，页面工具与登录态保持独立；工具权限受限场景
不会阻止独立的登录态授权。复制诊断仅写预览内存，并保留产品的原位反馈。

服务仅监听127.0.0.1，不读取账号、Cookie或真实浏览器配置，也不连接原生桥接、
下载服务或系统剪贴板。它是设计开发工具；真实权限、原生连接和浏览器弹窗
失焦关闭等行为继续由扩展环境验证。预览文件不进入扩展构建或发行产物。

## 检查

HTTP服务及源码身份检查包含在扩展测试中：

    npm --prefix browser-extension test

检查预览页面的场景切换、尺寸、主题、语言与操作：

    npm --prefix browser-extension run test:preview

浏览器检查使用独立无头浏览器，Windows默认Edge，其他平台默认Chrome。
可以通过AMEOW_BROWSER环境变量指定现有Chromium浏览器的可执行文件；
不会下载浏览器或操作日常用户配置。证据可写入AMEOW_PREVIEW_EVIDENCE指定的
目录；默认只打印检查结果。
