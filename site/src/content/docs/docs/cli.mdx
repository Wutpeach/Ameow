`ameow-cli` 让脚本和 Agent 操作本机当前用户的 Ameow 队列，与桌面端共用任务、组件和下载结果。无需另装扩展，也没有需要开启的 GUI 设置。

普通 CLI 控制桌面应用持有的队列；`dev` 入口仅供启用 `dev-tools` 的 debug 源码构建。

## 安装与调用

保留完整应用目录。Ameow 不会自动注册全局命令或修改 `PATH`；如需全局调用，可自行设置。

<span id="windows"></span><span id="mac"></span>

<Tabs syncKey="cli-platform">
<TabItem label="Windows">
<div>

`ameow-cli.exe` 与 `Ameow.exe` 位于同一目录。安装或完整解压后即可调用，保留应用目录结构。

在 PowerShell 中，将下列路径改成自己的实际安装或解压位置：

~~~powershell
$Cli = 'D:\Apps\Ameow\ameow-cli.exe'
& $Cli --help
~~~

也可自行把该目录加入用户 `PATH`，再使用 `ameow-cli --help`。从当前目录运行时使用 `./ameow-cli.exe`；上面的 `&` 是 PowerShell 调用带引号路径的语法。

</div>
</TabItem>
<TabItem label="Mac">
<div>

在完整 `Ameow.app` 中，入口是 `Contents/MacOS/ameow-cli`。例如应用放在 `/Applications` 时，在 zsh 或 bash 中运行：

~~~sh
cli='/Applications/Ameow.app/Contents/MacOS/ameow-cli'
"$cli" --help
~~~

若安装在 `~/Applications`，相应修改路径。可选的当前 shell 别名为：

~~~sh
alias ameow-cli='/Applications/Ameow.app/Contents/MacOS/ameow-cli'
ameow-cli --help
~~~

需要长期保留时，自行将别名加入所用 shell 的配置。请从原应用包调用，保留包内成员和签名。

## 提交并查看结果

准备一个公开媒体 URL，按上一节设置 CLI 路径。提交成功后，使用回执中的完整 `task_id` 查询或等待；`INSTANCE:JOB` 是完整 ID 的占位符。

<Tabs syncKey="cli-platform">
<TabItem label="Windows">
<div>

将 `$Url` 替换为实际媒体链接，再运行：

~~~powershell
$Url = 'https://example.com/media' # 换成实际媒体 URL
$Receipt = & $Cli --json submit $Url | ConvertFrom-Json
$Receipt
~~~

回执 `ok` 为 `true` 后，使用完整的 `task_id` 查询或等待：

~~~powershell
$Task = $Receipt.result.task_id
& $Cli --json show $Task
& $Cli --json wait $Task --timeout 300
~~~

</div>
</TabItem>
<TabItem label="Mac">
<div>

在 zsh/bash 中提交：

~~~sh
printf 'Public media URL: '
IFS= read -r url
"$cli" --json submit "$url"
~~~

从成功回执复制完整 `task_id`，替换下面的 `INSTANCE:JOB`，保留实例部分和任务编号：

~~~sh
task='INSTANCE:JOB'
"$cli" --json show "$task"
"$cli" --json wait "$task" --timeout 300
~~~

</div>
</TabItem>
</Tabs>

在 0.5.2 中，`submit` 在没有可连接实例时会启动相邻的普通应用，Windows 经过稳定启动入口；仍是桌面实例持有任务。其他任务和状态命令不启动应用。`--no-start` 可禁止提交时自动启动。

| 命令 | 用途 |
| --- | --- |
| `submit URL` | 提交，可选画质预设和 `--output DIR` |
| `list`、`show INSTANCE:JOB` | 列表或查看一个任务 |
| `wait INSTANCE:JOB --timeout 300` | 最多等待 300 秒，返回权威终态与实际文件 |
| `cancel INSTANCE:JOB`、`retry INSTANCE:JOB` | 取消或重试；重试后读取回执中的任务 ID |
| `settings`、`components`、`diagnose` | 读取偏好、组件状态或安全诊断；诊断可指定任务 ID |

表中的 `URL`、`DIR`、`INSTANCE:JOB` 均为占位符；URL 是否可下载由实际下载器和站点决定。画质参数为 `--quality highest`、`--quality balanced` 或 `--quality saver`；保存目录必须已存在。提交选项只影响本次任务，不改默认设置。

## 脚本需要注意

`--json` 让 stdout 只输出一个机器结果，日志不混入其中。`wait` 的退出码区分成功 0、部分成功 3、失败 4、取消 5、超时 6；其他错误和完整字段见仓库 [CLI 参考](https://github.com/Wutpeach/Ameow/blob/main/docs/cli.md)。

取消回执 `applied: true` 只表示取消意图受理。`Held` 或 `resources_released: false` 表示清理尚未确认，不能视为 Cancelled。CLI 退出、中断或等待超时不会取消桌面任务；实例重启后旧任务 ID 失效。

## 更新与源码构建

0.5.2 起 Windows 完整便携包也作为应用内更新载荷，CLI 随完整应用更新。Mac CLI 随完整应用包更新并参与包签名校验。请使用同一版本的应用与 CLI；协议不兼容会明确报错。

现在需要源码构建时，按[开发资料中的 CLI 入口](../developer/#cli)使用独立目录。普通控制 CLI 不要求 `dev-tools`；`ameow-cli dev` 是另一种仅 debug + `--features dev-tools` 可用的开发入口，release 构建明确拒绝该特性，正式包没有可开启它的设置开关。


## 0.5.3 开发版：Agent 工作流

以下示例需要包含这些功能的 0.5.3 开发构建；已发布的 0.5.2 包尚不支持媒体查询、精确切片及维护命令。使用匹配版本的桌面应用和 CLI，并把示例路径、URL 换成实际值。

~~~powershell
$Cli = 'D:/Apps/Ameow/ameow-cli.exe'
$Url = 'https://example.com/media'
$Output = 'D:/Downloads' # 已存在且可写的目录
$Info = & $Cli --json inspect $Url --quality balanced | ConvertFrom-Json
if (-not $Info.ok) { throw $Info.error.message }
& $Cli --json wait $Info.result.task_id --timeout 300
if ($LASTEXITCODE -ne 0) { throw "媒体查询未成功结算" }
$Job = & $Cli --json submit $Url --quality balanced --output $Output --start-ms 10000 --end-ms 30000 --precise | ConvertFrom-Json
if (-not $Job.ok) { throw $Job.error.message }
& $Cli --json wait $Job.result.task_id --timeout 300
~~~

Mac 安装 jq 后，可在 zsh/bash 中无交互地读取任务 ID：

~~~sh
cli='/Applications/Ameow.app/Contents/MacOS/ameow-cli'
url='https://example.com/media' # 换成实际可访问的作品链接
output="$HOME/Downloads"
info=$("$cli" --json inspect "$url" --quality balanced)
printf '%s\n' "$info" | jq -e '.ok' >/dev/null || exit 1
task=$(printf '%s\n' "$info" | jq -r '.result.task_id')
"$cli" --json wait "$task" --timeout 300 || exit 1
job=$("$cli" --json submit "$url" --quality balanced --output "$output" --start-ms 10000 --end-ms 30000 --precise)
printf '%s\n' "$job" | jq -e '.ok' >/dev/null || exit 1
task=$(printf '%s\n' "$job" | jq -r '.result.task_id')
"$cli" --json wait "$task" --timeout 300
~~~

成功提交回执包含以下字段，实际身份各不相同：

~~~json
{"ok":true,"result":{"task_id":"INSTANCE:1","job_id":1}}
~~~

查询只读取媒体信息，不下载文件。`inspect` 默认使用 highest；选择 `balanced` 或 `saver` 可查看相应预设。提交两个毫秒端点默认快切；上例的 `--precise` 显式选择精确切片。终态任务结果中 `files` 提供实际路径、字节数和 SHA-256；检查退出码和 `resources_released` 后再使用文件。

通过 `owner.capabilities` 核对支持情况。查询中未知的时长和规格字段为 `null`；`selected` 是按对应画质预设选中的来源规格摘要。`video_codec` 是来源编码，`bytes` / `size_source` 是来源大小或估计；最终成品的路径、字节数和 SHA-256 读取结算后的 `files`。快切可能包含附近关键帧边界，需要更贴合指定时间时使用 `--precise`。

~~~powershell
& $Cli --json list
& $Cli --json cancel $Job.result.task_id
& $Cli --json wait $Job.result.task_id --timeout 300
& $Cli --json retry $Job.result.task_id # 符合重试条件时读取新回执的 task_id
~~~

先读取偏好与会话状态；`settings set` 仅在需要修改默认值时单独执行：

~~~powershell
& $Cli --json settings
& $Cli --json sessions
~~~

~~~powershell
& $Cli --json settings set quality balanced
~~~

画质等同步偏好保存返回 `saved: true` 即已完成；无需等待 operation。

组件先检查并等待，读取每项真实检查结果：

~~~powershell
& $Cli --json components check
& $Cli --json components wait --timeout 60
& $Cli --json components
~~~

仅在检查成功、存在可安装的新版本时更新对应组件：

~~~powershell
& $Cli --json components update yt-dlp
& $Cli --json components wait --timeout 300
~~~

恢复推荐版本用于恢复场景，按需要单独执行：

~~~powershell
& $Cli --json components restore yt-dlp
& $Cli --json components wait --timeout 300
~~~

应用也先检查、等待并读取状态：

~~~powershell
& $Cli --json app status
& $Cli --json app check
& $Cli --json app wait --timeout 60
& $Cli --json app status
~~~

仅当检查结果提供可安装的新版本时下载；下载完成后再次读取阶段：

~~~powershell
& $Cli --json app download
& $Cli --json app wait --timeout 300
& $Cli --json app status
~~~

只有应用更新阶段为 `Ready` 时安装。安装会正常重启应用，保留回执身份来等待实际结果：

~~~powershell
$Install = & $Cli --json app install | ConvertFrom-Json
if (-not $Install.ok) { throw $Install.error.message }
& $Cli --json --instance-id $Install.instance_id --operation-id $Install.result.operation.id app wait --timeout 300
~~~

这些维护命令可能改变偏好、下载或安装组件及应用，请按需要逐项执行。`settings set` 保存默认值；提交选项只改变单次任务。`sessions` 只显示状态和缺失条件，站点授权仍在浏览器完成。组件可指定 `yt-dlp` 或 `gallery-dl`；再次运行 `components` 查看每项真实结果，运行 `app status` 查看应用更新阶段。`app quit` 和 `app restart` 遵循桌面停止规则，进行中的任务不会被强杀。受理或失联不代表操作已完成。

查看 `ameow-cli --help`、`ameow-cli help submit` 和 `ameow-cli components --help` 以发现完整参数、结果及恢复方式。

应用更新偏好返回异步 operation 时，使用 `settings wait --timeout 30` 确认保存。维护回执包含 `operation.id`、`action`、`phase`、`done`、`success` 和 `error`；只有 `done: true` 且 `success: true` 才表示完成。等待失败退出 4，超时退出 6，操作继续。

`app install`、`app quit` 和 `app restart` 需保留原回执的 `instance_id` 与 `operation.id`；原 owner 退出后，用 `--instance-id ORIGINAL_INSTANCE --operation-id OPERATION_ID app status` 查询，或配合 `app wait --timeout 300` 等待。安装核对实际接受的安装版本，重启核对新 owner 握手，退出核对进程结束。安装和退出/重启分别仅保留最近一份回执，新操作替换旧回执；超时或缺失回执仍表示结果未确认。
