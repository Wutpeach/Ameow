---
title: 基础概念
description: 理解 Ameow 的悬浮窗口、输出目录、下载队列、浏览器扩展和设置如何配合工作。
---

Ameow 的使用模型可以概括为一句话：你把内容交给悬浮窗口，Ameow 按当前设置把它保存到输出目录；如果内容来自网页，任务会进入下载队列；如果网页需要更多上下文，浏览器扩展负责把这些上下文送到桌面端。

## 五个核心对象

| 概念 | 它是什么 | 你需要记住什么 |
| --- | --- | --- |
| 悬浮窗口 | 桌面边缘的小入口 | 文件、文件夹和链接都先交给它 |
| 输出目录 | 保存结果的位置 | 文件最终在哪里，取决于当前输出目录 |
| 下载队列 | 管理网页下载任务的状态 | 等待、准备中、下载中、转换中、完成、失败 |
| 浏览器扩展 | 连接网页和桌面端的桥 | 需要登录态或页面上下文时很重要 |
| 设置 | 控制偏好和行为 | 输出目录、快捷键、质量、兼容格式都在这里调整 |

## 悬浮窗口不是传统主窗口

Ameow 的核心入口是小型悬浮窗口。它适合长期放在桌面边缘，让你随时拖入文件或粘贴链接。它不要求你每次都打开一个完整管理界面。

你常做的动作是：

- 拖入文件：复制到输出目录。
- 拖入文件夹：切换输出目录。
- 粘贴链接：创建下载任务。
- 双击或右键：打开当前输出目录。

## 输出目录决定文件去哪里

默认输出目录通常是 `Desktop/Ameow_Received`。但只要你拖入过文件夹，当前输出目录就可能已经切换。

因此找文件时，最可靠的方式不是凭记忆找默认目录，而是从 Ameow 打开当前输出目录。

## 下载队列解释任务状态

网页链接不一定会立刻变成文件。它可能经历：

1. 等待：排队中。
2. 准备中：解析链接、检查格式、准备下载依赖。
3. 下载中：正在传输文件。
4. 转换中：正在合并或转成更兼容的格式。
5. 完成：最终文件已写入输出目录。
6. 失败：需要按失败原因排查。

理解状态能帮助你判断应该等待、检查网络，还是排查站点和登录态。

## 浏览器扩展负责网页上下文

只复制 URL 时，桌面端拿到的通常只是一个链接。某些站点还需要当前页面、登录态、Cookies、播放器状态或站点专用入口。浏览器扩展就是为这些场景准备的。

扩展不是替代桌面端。它要连接正在运行的 Ameow 桌面应用，才能发送任务。

## 设置不需要一开始全部配置

第一次使用时，只需要确认 Ameow 能启动、能收集文件、能打开输出目录。之后再根据工作习惯调整：

- 输出目录：控制文件保存位置。
- 快捷键：快速唤起窗口。
- 下载质量：平衡画质、体积和稳定性。
- AE 兼容格式：让视频素材更适合后期软件。
- 开机启动：让 Ameow 登录系统后自动可用。

## 一个完整例子

你正在整理一个视频项目：

1. 把项目素材文件夹拖入 Ameow，切换输出目录。
2. 把散落在桌面的图片拖入 Ameow，复制到项目目录。
3. 在浏览器里打开视频页面，通过扩展发送下载任务。
4. 下载队列显示任务准备、下载、转换。
5. 完成后，从 Ameow 打开输出目录，文件已经进入项目目录。

这就是 Ameow 的核心工作流。
