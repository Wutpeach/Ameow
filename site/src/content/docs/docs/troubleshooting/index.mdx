## 下载失败

先看队列提示，按发生阶段处理：

| 现象 | 处理方法 |
| --- | --- |
| 链接被拒绝 | 使用[支持的公开媒体入口](../supported-sites/)，移除视频播放列表或系列参数。 |
| 组件准备失败 | 打开[组件与诊断](../desktop/settings/#components)，按提示重试或恢复推荐版本。 |
| 请求被拒绝或限流（403 / 429） | 等待后重试。状态码不能单独确定原因；站点、权限或网络变化都可能影响结果。 |
| 画质不可用 | 站点没有符合当前画质设置的视频格式。更换画质后重新提交链接；重试原任务仍用原画质，不会自动缩小源视频。 |
| 保存失败 | 检查任务提交时的目录是否存在、可写且空间足够。更改目录后需要提交新任务。 |
| 退出时清理异常 | 按应用提示等待或重试清理；收起界面不会撤销退出。 |

最终失败或部分完成的任务可按界面重试；原画质和目录保留。需要登录或地区权限的内容即使能在浏览器播放，也可能无法下载。

## 组件更新失败

「检查更新」失败，只表示本次未取得可用的更新检查结果。下载或启用组件新版失败，表示本次更新尚未完成。当前正在使用哪个版本，以对应组件行显示的实际版本为准。

队列中的视频解析、提取或下载失败发生在下载器处理媒体时，需要另行排查。

<Steps>
1. 打开[组件与诊断](../desktop/settings/#components)，查看对应组件行的**实际版本**。悬停更新按钮看到的是目标版本；发现新版或另一组件更新成功，都不代表当前组件已切换。
2. 按失败提示检查网络或代理后再手动检查、更新。遇到 403 / 429 时，先等待服务给出的重试时间；没有时间提示时稍后再试。状态码可能来自不同服务，不能据此认定是 GitHub 限流，连续点击不会解决拒绝请求。
3. 仍然失败时，用页面现有的复制诊断按钮反馈。诊断可包含对应组件、目标与实际版本，以及可得的失败阶段、服务和 HTTP 状态；没有取得的信息保持未知。附上发生时间和操作步骤，勿补发 Cookie、令牌或原始私密响应。
4. 若问题发生在主动选择新版之后，可从该组件的更多菜单选择「恢复推荐版本」。它只恢复对应组件，不改变另一个下载器的选择；健康推荐缓存可复用，缺失时仍需获取并验证。恢复失败时保留诊断，不要清空数据或从未知来源替换程序。
</Steps>

组件已是预期版本但媒体仍失败时，回到[下载失败](#downloads)排查；更新组件不能保证绕过站点登录、地区权限或内容限制。

## 找不到文件

<Steps>
1. 确认队列显示完成，后处理结束前继续等待。
2. 打开[保存目录](../desktop/output-folder/)。提交后若切换过目录，查看任务原来的位置；重试也沿用原目录。
3. 若任务失败，解决目录权限或空间问题后重新提交。用户数据目录不是下载文件的替代位置。
</Steps>

<span id="editor-audio"></span>

## 编辑器中没有声音

播放器有声而编辑器没有音轨时，请保留原件并检查编辑器版本、容器和音视频编码，不要只修改文件后缀。普通 SDR 视频的默认兼容输出使用 MP4、H.264 与 AAC；HDR 和历史文件可能沿用其他格式。编辑器是否能导入仍以实际文件和编辑器版本为准。

## Mac 入口与启动

Mac 默认在菜单栏运行，没有 Dock 图标。关闭设置窗口不会退出应用，可从菜单栏再次打开。

<ManualFigure kind="mac" />

看不到悬浮窗口时先从菜单栏选择打开，或切回普通桌面。

<details>
<summary>窗口、粘贴与启动详情</summary>

Compact 跟随普通 Spaces，不覆盖其他应用的全屏空间；此行为不适用于 Full 或设置窗口。

在 Full 按 `Command+V` 粘贴；Full 右键菜单没有粘贴项。如果没有响应，请在反馈中附上应用版本、入口和操作步骤。

系统阻止启动时，核对[安装版本与来源](../downloads/)，保留完整系统提示再反馈。开机启动或更新的授权按系统提示处理，见[设置与更新](../desktop/settings/)。

</details>

## 反馈问题

从失败任务或组件与诊断页复制诊断，附上系统／应用版本、发生时间和可复现步骤，在 [GitHub Issues](https://github.com/Wutpeach/Ameow/issues) 查询或反馈。

<Aside title="发送之前">
检查诊断内容，隐藏私人路径、私有链接和登录信息。普通排障无需清空应用数据。
</Aside>
