---
title: 故障排查
description: 按启动、扩展连接、下载失败和文件位置四类现象快速定位 Ameow 问题。
---

遇到问题时，先判断现象属于哪一类。不要一开始就重装应用或重复下载；先确认当前状态，通常能更快定位原因。

最快的原则是：**启动问题看系统拦截，扩展问题看 `Connected`，下载问题看任务状态，文件问题看当前输出目录。**

## 30 秒定位

| 你看到的现象 | 优先判断 | 进入页面 |
| --- | --- | --- |
| macOS 提示无法验证开发者、无法打开应用 | 应用是否已拖入 `Applications`，是否尝试过右键打开 | [macOS 首次启动](./macos-first-run/) |
| 浏览器扩展显示 `Disconnected` | 桌面端是否正在运行，扩展是否需要重载 | [扩展未连接](./extension-disconnected/) |
| 界面或日志里出现错误提示、英文关键词或 `E_...` 错误码 | 先按提示文字判断登录、网络、依赖、输出目录等方向 | [错误提示与错误码](./error-messages/) |
| 粘贴链接没有任务、一直准备中或失败 | 任务卡在哪个阶段，链接和输出目录是否正常 | [下载失败](./download-failures/) |
| 显示完成但找不到文件 | 当前输出目录是否被切换，任务是否真的完成 | [找不到文件](./missing-files/) |

## 如果是启动问题

macOS 首次启动被拦截时，优先按“拖入 Applications → 右键打开 → 系统设置放行 → quarantine 命令”的顺序处理。不要一开始就执行命令。

Windows 上如果应用无法启动，先确认你下载的是 Installer EXE 或 Portable ZIP，而不是源码包。

## 如果是扩展问题

扩展必须连接正在运行的桌面端。先启动 Ameow，确认悬浮窗口可见，再打开扩展弹窗。`Connected` 才表示可以发送网页任务。

如果扩展已连接但下载失败，问题通常转到站点支持、登录态、链接有效性或输出目录。

## 如果有明确错误提示

先保留完整错误提示或截图。如果提示里包含 `cookies`、`403`、`timeout`、`yt-dlp exited` 或 `E_AUTH_REQUIRED` 这类错误码，先看 [错误提示与错误码](./error-messages/) 判断方向，再回到下载失败页面执行具体排查。

## 如果是下载问题

先看任务状态：

- 没有任务：链接没被接收，或扩展没连上。
- 一直准备中：可能是网络、依赖、登录态或站点规则。
- 明确失败：检查链接、站点支持、输出目录权限。
- 完成但没文件：转到文件位置排查。

## 如果是文件位置问题

从 Ameow 打开当前输出目录。不要只看默认 `Desktop/Ameow_Received`，因为拖入文件夹会切换输出目录。
