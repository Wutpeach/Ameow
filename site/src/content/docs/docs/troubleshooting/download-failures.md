---
title: 下载失败
description: 按任务未出现、准备中、失败、完成但找不到文件四种情况排查 Ameow 下载问题。
---

下载失败不要先反复重试。先判断任务卡在哪一步，再按对应分支处理。最常见原因是链接无效、输出目录不可写、站点需要登录态、扩展未连接，或首次下载依赖还在准备。

本页的核心判断只有四类：**任务没出现、一直准备中、明确失败、完成但找不到文件。** 先分清类型，再处理。

[示意图：下载失败排查决策树，从任务未出现、准备中、失败、完成但找不到文件四种情况分支]

## 先做 30 秒快速判断

先回答这 4 个问题：

1. 粘贴或发送后，Ameow 里有没有出现任务？
2. 任务是一直准备中，还是已经显示失败？
3. 链接能不能在浏览器里正常打开和播放？
4. 当前输出目录能不能写入文件？

如果你已经知道卡在哪一步，直接看下面对应分支。不要同时改质量、换目录、重装扩展和升级版本，否则很难判断到底是哪一步修好了问题。

## 分支 A：任务完全没有出现

这种情况通常说明 Ameow 没有收到链接，或链接没有被识别。

按顺序检查：

1. 确认 Ameow 桌面端正在运行，悬浮窗口可见。
2. 重新复制链接，确认剪贴板里是完整 URL。
3. 点击 Ameow 悬浮窗口或让它处于可接收状态，再按 `Ctrl+V`；macOS 使用 `Cmd+V`。
4. 如果通过浏览器扩展发送，先确认扩展弹窗是 `Connected`。
5. 换一个公开链接测试，确认不是当前链接本身的问题。

处理后应该看到任务进入等待、准备中或下载中。如果仍完全没有任务，优先排查扩展连接或链接格式。

## 分支 B：任务一直准备中

准备中通常表示 Ameow 正在解析链接、读取站点信息、准备下载组件，或等待依赖就绪。

按顺序检查：

1. 等待一小段时间，首次使用某些下载能力可能需要更久。
2. 确认网络可访问该站点。
3. 如果内容需要登录，保持浏览器已登录，并通过浏览器扩展发送任务。
4. 如果站点刚刚改版，当前版本可能需要更新规则；查看最新稳定版或 Release Notes。
5. 重启 Ameow 后再次发送同一链接。

如果多个站点都一直准备中，可能是下载依赖准备异常。此时查看 [下载依赖与自动准备](../../advanced/download-dependencies/) 的背景说明，但当前页面的处理动作仍是：等待、重启、换公开链接验证、升级到最新稳定版。

## 分支 C：任务显示失败

[截图：下载队列中某个任务显示失败状态和错误提示区域]

失败任务优先看错误发生的位置：

### 链接打不开

在浏览器里打开链接。如果浏览器也打不开，Ameow 无法下载。请换有效链接。

### 页面能打开，但需要登录

先在浏览器里登录对应站点，再通过 Ameow 浏览器扩展发送任务。只复制链接时，桌面端不一定能获得页面登录态。

### 弹窗里能看到资源，但无法预览或下载

先看资源是否带有 `[桌面端]` 标记。带标记的资源通常不是浏览器可以直接保存的完整文件，常见例子包括 `m3u8`、`mpd`、`.cmfv`、`.m4s`、`ts`、`blob:` 链接、音视频分离轨道或需要登录态的资源。

这类资源需要桌面端解析页面、选择轨道、合并、转码或使用登录态。请确认桌面端已连接，并且你在具体内容页发送任务。如果桌面端已连接仍失败，再继续按站点支持、登录态、代理环境和页面类型排查。

### YouTube 在浏览器能播放，但 Ameow 仍失败

这类情况经常不是“链接坏了”，而是代理环境不一致：

- 浏览器本身走了代理，但桌面端下载链路没有走到同一条网络路径。
- 代理软件只接管了浏览器，没接管 Ameow 或下载器子进程。
- 当前代理模式对 Bilibili 这类国内站点没影响，但对 YouTube 会直接体现为格式探测失败、下载失败或长期准备中。

优先建议仍然是让你的代理工具接管网络，因为浏览器、Ameow、pip、yt-dlp / gallery-dl 可能访问不同主机。TUN / 全局 / VPN / 系统代理模式通常最容易保持一致。

Ameow 也提供了一个低交互的手动代理设置：打开 **设置 → 系统与支持 → 网络代理**，选择 **手动代理**，输入不带账号和路径的 HTTP(S) 代理，例如 `http://127.0.0.1:7890`。格式合法后会自动保存并应用；Ameow 会用 GitHub、Deno、PyPI 等固定基础服务做自动检测。如果检测不可用，Ameow 会自动回退到系统代理，不会继续使用不可用的手动代理。

每个下载任务会按统一优先级解析一条网络路由：手动代理 > 系统代理（按目标网址解析）> 环境变量代理 > 直连。解析结果会应用到 yt-dlp / gallery-dl 子进程（环境变量代理同样按目标网址计算，`NO_PROXY` 命中时会明确走直连），下载器不再自行继承未选择的代理环境变量。如果系统返回多个代理候选或格式异常、不支持的条目，Ameow 不会猜一个代理套上去，而是给出明确的不支持诊断并停止该次下载。Electron 无法区分单个候选结果来自 PAC 脚本还是固定系统路由；无论哪种情况，Ameow 都只把它当作对当前条目网址生效的一条系统路由，不会声称其他主机也走同一决策。系统/环境路由只保证对当前条目网址生效，不代表视频 CDN 等下游主机走同一条代理。

不要在代理设置里测试某个失败的视频链接。单个内容链接失败可能是登录态、地区限制、账号权限、反爬或站点规则变化，不一定是代理问题。

按顺序处理：

1. 先确认当前 YouTube 视频页能在浏览器里正常播放。
2. 优先在具体视频页里通过扩展发送任务，不要在首页、搜索页或推荐流里测试。
3. 如果你正在使用代理软件，优先尝试它的 TUN / 全局 / VPN / 系统代理接管模式。
4. 如果系统代理模式无法覆盖 Ameow 或下载器子进程，再在设置里配置手动 HTTP(S) 代理。
5. 再用一个公开、无需登录的 YouTube 视频测试。
6. 如果最高质量失败，先切到均衡质量验证链路是否恢复。

如果切到代理工具的全局接管或手动 HTTP(S) 代理后问题明显缓解，通常就说明故障点在代理环境，而不是链接本身。

### 站点不在支持范围内

Ameow 不承诺所有网页都能下载。当前重点站点包括 YouTube、Bilibili、X / Twitter、Douyin、Xiaohongshu。其他站点可能可用，也可能随版本变化。

### 输出目录不可写

打开当前输出目录，尝试新建一个临时文件。如果不能创建，说明目录不可写。换一个你有权限的目录，再重新下载。

### 质量或格式选择过高

最高质量可能需要更复杂的格式探测、音视频合并或转换。如果持续失败，可以先选择更稳的质量偏好，再确认链接本身可下载。

## 分支 D：显示完成，但找不到文件

这通常不是下载失败，而是文件位置判断错误。

1. 从 Ameow 打开当前输出目录。
2. 确认你是否曾经拖入文件夹，导致输出目录切换。
3. 检查文件名是否被重命名规则修改。
4. 按修改时间排序，查看最新文件。

如果输出目录里仍没有结果，再回到任务状态确认它是否真的完成，而不是仍在转换中。

## 什么时候升级版本？

下面情况建议升级到最新稳定版：

- 同一个站点大量链接突然失败。
- Release Notes 提到对应站点、扩展连接、下载质量或打包修复。
- 你正在使用预发布版，想回到稳定行为。
- 你遇到的问题只在旧版本出现。

升级前先记录当前版本、站点、链接类型和任务状态。这样后续反馈问题时更容易定位。升级后建议用同一个公开链接复测一次，确认问题是否已经变化。
