# release-integrity Specification

## Purpose

定义当前 Windows 构建、签名和交付的安全及兼容边界。取代旧 R11 Gate A/B 审核文件流程；本规范记录既有发行机制，不授予本次迁移公开上传或签发权限。

## Requirements

### Requirement: 同源真实构建与材料

构建 SHALL 使用现有单入口、locked/offline、指定 Windows x64/MSVC 工具链、static CRT 和新输出目录，记录 Commit/tree、dirty、实际源码/资源/Cargo.lock/工具链和二进制身份并核验材料字节哈希。MUST NOT 要求已取消的 approval 状态、review 文件、reviewer 身份或构建前 Tag。dirty 开发输入可准备未签名材料，正式签名拒绝 dirty/合成身份；构建与打包不自动签名或上传。

#### Scenario: 已有输出目录或构建期间输入变化

- **WHEN** 输出已存在或输入/打包实现发生变化
- **THEN** 拒绝覆盖或混用，保留原件与证据。

### Requirement: 生产可信根与完整性

正式签名/交付 SHALL 拒绝空生产根、fixture 根、版本/roots 不匹配、无效签名和修改后的 ZIP/EXE/notices/成员。私钥 SHALL 留在仓库和候选目录之外，CI 不生成或使用生产私钥；fixture 只可用于显式 debug/test 并明显标记。取消旧审核 Gate 不代表免除真实第三方许可、来源、署名和发行主体义务。

#### Scenario: 将测试资产改名为正式包

- **WHEN** fixture 或篡改资产被交付工具接收
- **THEN** 真实信任/签名/身份校验拒绝，改名或修改状态字段不能成为生产权威。

### Requirement: 唯一最终核心与显式公开授权

Windows 安装 EXE 与完整 portable ZIP、Mac 完整 App ZIP 及两平台签名更新 JSON SHALL 构成五项发行资产，来自各平台匹配的最终签名核心并核对成员及哈希。Windows 完整 portable ZIP SHALL 同时作为后续应用内更新载荷，不再输出独立单 EXE 更新 ZIP；Mac 完整 App ZIP 与签名清单保留。Tag 若存在 SHALL 指向签名构建对应 Commit；不得移动历史 Tag、覆盖远端资产或把本地验签当作公网 HTTPS 验收。公开 Tag/Release/上传需要当前明确授权；本机准备、CI 成功和历史私有验收均不自动授权。

#### Scenario: 本地候选尚未公开

- **WHEN** 本地签名、完整包切换或损坏拒绝已验证，但公开 Release 尚不存在
- **THEN** 保留本地结果，真实公网清单及包验证仍标为未完成，公开下载链接继续指向已发布版本。

### Requirement: 保持已有用户身份与证据边界

工程根级 Rust/GPUI 身份 SHALL 保留既有 AmeowNext 数据位置、设置/运行时选择/历史/缓存和 Windows 注册状态兼容；规范迁移不搬迁用户数据、导入 Electron 配置或重新注册启动项。历史路径与 Git 保全、忽略产物的恢复范围 SHALL 区分，未核对原始资料不得据此删除工作树、发布快照或历史证据。

#### Scenario: 开发文档或工程名称调整

- **WHEN** 新文档采用当前根路径或 Ameow 名称
- **THEN** 不把旧命令/旧原生结果解释成新路径或新产物验证，不由文档整理触发数据迁移或发行。

### Requirement: Windows 安装器默认跟随显示语言

Windows 安装器 SHALL 按当前用户的 Windows 显示语言默认选择中文或 English，中文显示语言覆盖简体和繁体；未支持语言回退 English。区域、数字或日期格式 MUST NOT 决定界面语言。内置安装、卸载流程和安装器自有选项、进度、检查及失败提示 SHALL 使用所选语言，允许显式语言覆盖。

#### Scenario: 显示语言和区域格式不同

- **WHEN** 用户显示语言为中文或 English，但区域格式使用另一语言
- **THEN** 默认界面跟随显示语言；以前安装时保存的语言不覆盖当前默认。

#### Scenario: 繁体中文或未支持语言

- **WHEN** 显示语言为繁体中文，或为未支持的非中文语言
- **THEN** 前者默认中文，后者默认 English，全部现有页面及自有提示均有对应语言。

### Requirement: Windows 安装器紧凑展示与隔离验证

安装器 SHALL 复用正式 Ameow 应用图标，以紧凑原生窗口呈现完整流程，随实际 DPI 缩放，保留文字、按钮及键盘操作，不裁切必要内容。验证 SHALL 区分普通候选和隔离测试变体，记录准确源码、安装器哈希、实际中英窗口及覆盖限制；MUST NOT 改系统语言、覆盖日常安装/配置/Store/队列，或为验证终止用户程序。既有签名、版本校验、正常退出和注册语义保持。

#### Scenario: 查看中英安装流程

- **WHEN** 在受测 DPI 逐页查看中英文安装与必要提示
- **THEN** 正式图标、步骤、内容、进度与按钮可见且可操作；证据说明实测 DPI 和未测范围。

### Requirement: Windows 稳定入口与完整配套

Windows 0.5.2 起完整安装版及完整 portable SHALL 包含清楚的根目录 Ameow.exe 稳定启动器，并嵌正式品牌图标、FileDescription 和版本资源；桌面、开始菜单、开机启动和内部调用 SHALL 使用该入口。版本文件可保存在内部 versions 目录，CLI、host 与扩展 SHALL 随主程序完整交付。MUST NOT 为入口增加根 README/TXT，或把开发 cargo run 的主程序替换为启动器。0.5.3 安装器 SHALL 为可识别的 0.5.1 旧布局提供保留用户数据的原目录转换，为 0.5.2 起的完整布局提供原目录升级及相同签名版本修复；MUST NOT 将旧内部状态直接作为新完整版本的已接受状态，或建立旧单 EXE 应用更新载荷桥接。

#### Scenario: 隔离安装后的实际快捷方式

- **WHEN** 用本任务自有目录及独立快捷方式安装新完整包
- **THEN** 核实实际快捷方式目标、图标来源及 Shell 提取的正式图标，运行该快捷方式确认主程序启动；安装器自身图标及图标缓存推测不能代替此证据。

#### Scenario: 完整重装目录仍保留旧布局状态

- **WHEN** 所选程序文件夹含可识别旧布局且没有新稳定入口清单
- **THEN** 安装器完成可恢复的旧程序状态转换后继续安装，保留设置、授权会话、下载及无关文件，失败提供明确恢复路径；无法证明归属或存在重解析点时停止并指出原因，MUST NOT 递归清空目标目录。

#### Scenario: 同布局升级及同版修复

- **WHEN** 0.5.2 起的完整布局在原目录安装可信新版本，或重新安装同一签名版本
- **THEN** 新版本保留旧完整版本、状态的防重放保护和 Ready 确认；相同签名版本可修复而不降级，改变后的同版槽冲突仍拒绝，启动器及快捷方式指向根稳定入口。

### Requirement: 完整版本事务与失败恢复

Windows 后续应用更新 SHALL 验签并校验完整载荷和全部配套成员，只在真实启动 Ready 确认后将整套版本设为当前；缺件、篡改、非法路径、重放或启动失败 SHALL 安全拒绝并保留可运行的旧完整版本。固定扩展磁盘路径 SHALL 与已确认活动版本匹配，镜像失败 MUST NOT 宣称切换完成；中断后下一次启动 SHALL 修复派生镜像并继续正确旧版或候选处理。稳定 CLI/host SHALL 分派至已验证活动版本。

#### Scenario: 完整组件升级与回退

- **WHEN** 明确身份的新契约消费者接收更高版本完整包，或该候选未 Ready、成员损坏
- **THEN** 前者确认后主程序、CLI、host、扩展全部匹配新版本，后者恢复整套旧版本；保留实际消费者、源码及包身份，静态公钥或新版 NoUpdate 不能充当真实升级结果。

#### Scenario: 下载完成但尚未活动

- **WHEN** 新包仅已下载到 Ready，或已确认活动并成功更新固定扩展目录
- **THEN** 仅后者代表磁盘配套扩展已更新；浏览器已加载代码仍须手动重载扩展及刷新网页，不假称浏览器自动更新。

#### Scenario: 首次安装与升级期间的配套分派

- **WHEN** 首次安装尚无已接受版本，或已有版本正在试运行新升级
- **THEN** 前者只允许完整验证且未标记失败的首次安装候选（pending/trial）供根 CLI/host 使用，Ready 后使用已接受版本，首次失败后拒绝分派；后者始终优先已接受 current，不把未确认升级交给根配套入口。

#### Scenario: 可信旧格式没有更新

- **WHEN** 签名以及产品、通道、目标、合法版本身份均已验证的清单不比本地新，即使其载荷格式属于旧版
- **THEN** 安静显示无更新且不下载或安装；保留已验证 Ready 及安装授权反馈，不制造安全失败提醒。未认证或身份错误仍拒绝；真正较新候选继续完整新契约验证，格式不支持与安全失败分别反馈，不建立旧载荷安装桥接。

### Requirement: 精简许可物料保留适用正文和来源

发行包 SHALL 随实际交付软件保留适用版权、许可正文及 NOTICE 的离线可读副本；相同条款可以共用正文，但组件和版权映射 MUST 完整。仅工程审计用途的 inventory、哈希来源和构建上下文 SHALL 留在对应源码版本，不无区别复制到发行包。精简 MUST NOT 以致谢或远端链接替代必须随副本提供的声明，也不得回改已发布资产。

#### Scenario: 多个组件使用相同许可条款

- **WHEN** 多个实际依赖或标准库组件使用同一正文
- **THEN** 包内可保存一份共用正文及准确映射，保留不同版权和适用 NOTICE，全部材料无需网络即可阅读。

#### Scenario: 审计资料移出发行包

- **WHEN** 完整来源 inventory 或编译器上下文只用于工程追溯
- **THEN** 对应源码版本继续保留它们，发行成员仍有来源及字节校验，必要许可和版权保持随包。

### Requirement: 许可精简兼容完整更新并分开测量占用

Windows 许可物料精简 SHALL 保持已发布消费者的完整更新和版本槽校验，不移除旧消费者必须的根镜像。收益 SHALL 分别记录 ZIP 压缩数据和整体字节、安装器字节、解压逻辑大小及安装分配大小；未实测的指标 MUST 标记未知，不以逻辑大小推算压缩或独占物理收益。

#### Scenario: 已发布消费者接受完整候选

- **WHEN** 0.5.2 消费者下载使用精简许可的新完整版本
- **THEN** 根入口、完整版本槽、CLI、host、扩展和全部必需镜像通过既有成员与哈希校验，许可精简不破坏升级和回退。

### Requirement: Windows 卸载的数据保留与归属

独立卸载 SHALL 默认保留用户数据，并提供默认不勾选的“同时删除用户数据”，就近说明清除设置、已授权会话、组件缓存、诊断及自有任务临时数据，保留下载成品和浏览器原账号/Cookie。升级中的布局转换 SHALL 保留用户数据。文件、版本槽、自启动、快捷方式及 Native Host 清理 SHALL 核对本安装归属和多副本使用，MUST NOT 越过重解析点清理或将部分失败报告为全部完成。

#### Scenario: 默认保留与明确清理

- **WHEN** 用户取消勾选或明确勾选用户数据清理后卸载
- **THEN** 前者保留用户数据，后者只删除告知且能确认归属的自有数据；两者均保留下载成品、浏览器原数据和无法确认归属的文件，清理失败列出具体未清项及可行下一步。

#### Scenario: 默认、自选与历史保存目录的成品均保留

- **WHEN** 用户勾选删除用户数据，且已下载成品位于默认下载目录、自选目录或以前使用过的保存目录
- **THEN** 所有这些已交付成品均保留；是否修改默认位置不改变保留规则，清理只回收可确认归属的应用数据和任务临时内容。

#### Scenario: 同一用户存在另一副本

- **WHEN** 另一个安装或便携副本仍使用共享数据或系统接线
- **THEN** 卸载不删除其接线或共享数据，说明保留原因；本安装的程序清理仍可独立完成。

### Requirement: Windows 安装与数据位置的正常路径支持

安装、升级、启动器、组件调用、扩展接线和卸载 SHALL 支持中文及空格安装路径、中文用户与输出路径。存储说明 SHALL 区分实际安装目录的程序/版本槽/应用更新与每用户数据域的设置/组件归档/任务工作区/诊断/授权会话；成品输出至其他磁盘不意味着工作区随之移动。MUST NOT 将本版表述为新增缓存位置选择或数据迁移，或承诺擦除 Windows 系统维护的运行历史。

#### Scenario: 中文路径及不同输出盘

- **WHEN** 用户将程序和成品分别放在包含中文或空格的目录
- **THEN** 受影响流程按正常支持运行，文档明确用户数据域及任务中间媒体仍可能占用其所在磁盘，不要求改用英文路径。
