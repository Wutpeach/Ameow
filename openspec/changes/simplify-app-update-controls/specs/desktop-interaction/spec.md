# Spec Delta

## ADDED Requirements

### Requirement: 应用自动更新与提醒各司其职

关于页 SHALL 仅保留自动更新、更新提醒两个默认开启的策略开关与始终可见的检查更新入口，并按真实阶段提供手动动作。自动更新开启时自动检查、后台下载并在安全空闲时安装；关闭仍检查，由用户决定下载与安装。提醒只控制 Full 应用更新显示，不改变策略或关于页结果，不屏蔽依赖故障及扩展更新。

#### Scenario: 已下载更新后继续主动检查
- **WHEN** 更新已就绪，且没有实际处理中操作或短暂检查限流
- **THEN** 仍能主动检查；相同候选不重复下载或清除，检查失败须准确反馈并保留经重新验证的有效安装入口。

#### Scenario: 重查不清除已有授权阻断
- **WHEN** 已就绪候选有安装失败或授权取消反馈，用户重新检查成功、失败或关闭自动更新中断重查
- **THEN** 有效候选及原安装反馈保留，不因重查重新自动申请授权；检查错误在关于页独立反馈，不覆盖 Full 的原有阶段与操作。

#### Scenario: 自动更新开且提醒开
- **WHEN** 两个开关均开启并发现可信新版本
- **THEN** 后台下载，在任务结束且资源释放后的合适空闲时机安装；Full 显示状态和手动入口，不将策略降为仅手动。

#### Scenario: 自动更新开且提醒关
- **WHEN** 自动更新开启而提醒关闭
- **THEN** 检查、下载和安全空闲安装继续，Full 应用更新分支隐藏。

#### Scenario: 自动更新关且提醒开
- **WHEN** 自动更新关闭而提醒开启并发现新版本
- **THEN** Full 提醒并提供直接操作，只有显式动作才启动下载或安装；悬停、展开及切换提醒不触发下载。

#### Scenario: 自动更新关且提醒关
- **WHEN** 两个开关均关闭
- **THEN** 继续检查，Full 隐藏应用更新，用户仍能在关于页检查、查看结果及手动更新。

#### Scenario: 按需查看自动更新说明
- **WHEN** 用户打开自动更新标题旁的 info
- **THEN** 开启态显示“自动检查、后台下载，任务结束且资源释放后，在合适的空闲时机重启安装。”；关闭态显示“继续检查并提醒有新版本，由用户决定下载和安装。”，并提供对应英文。

### Requirement: Full 更新操作对应实际阶段

Full SHALL 复用既有左下图标及浮窗，应用更新行直接执行当前可用动作，不能只跳设置。下载和验证中显示真实进度且不接受重复操作；已就绪可请求安全安装；已请求等待任务或切换时不可重复提交；失败可显式重试。应用提醒与组件、扩展分类独立，悬停本身无副作用。

#### Scenario: 未下载的新版本
- **WHEN** 自动更新关闭且用户仅悬停后点击下载更新
- **THEN** 悬停阶段不下载，点击后才下载并在原入口呈现进度，不要求先打开关于页。

#### Scenario: 等待与失败
- **WHEN** 安装已请求但任务未结束，或更新失败
- **THEN** 等待时继续原任务并准确说明已安排，不重复请求；失败保留准确反馈和可用重试动作。

### Requirement: 应用更新保留个人意图及安全空闲

应用 SHALL 保留现有个人配置。旧 auto_check、auto_download、idle_restart 任一已存值为 false 时映射为自动更新关闭；全为 true 或没有旧限制时自动开启，提醒缺省开启；新双开关保存后按新值恢复。自动安装须同时满足真实队列完成、共享准备与全部资源释放，并避开近期应用交互；手动安装同样不得强行打断任务。

#### Scenario: 旧配置包含关闭意图
- **WHEN** 升级或重新安装后读取任一旧 false 偏好
- **THEN** 自动更新关闭且不清空其他设置；新用户两个开关默认开启，读写失败不伪报保存成功。

#### Scenario: 任务结束但资源尚未释放或用户正在操作
- **WHEN** 候选已就绪而任务、准备、资源或近期交互仍不满足空闲
- **THEN** 不自动重启；持续满足空闲后再次核对安全门与偏好，才申请安装，自动和手动均沿原事务结算。
