# Design

## Context

动机见 proposal.md。应用更新已有单一后台 owner、独立偏好 JSON、真实队列安全门和完整安装事务。Full 组件提示与应用更新共用现有浮窗；多个 owner 并行开发，共享文件仅做约定的最小分支接线。

## Goals / Non-Goals

Goals：复用原保存及安全门，让双开关真实影响后台策略，手动动作就近执行。

Non-Goals：不改完整载荷事务、依赖策略、扩展策略或窗口框架，不写主 spec，不进行发行。

## Decisions

- 偏好只保存 auto_update / notify_updates。反序列化读取旧三字段，任一已存 false 均保守映射为自动关闭；不把旧 idle_restart=false 静默升级为允许重启。新字段优先，缺提醒值为 true。相比按旧默认推测用户意图，这避免覆盖真实关闭。
- 检查调度不再读取自动开关；仅下载及自动安装受 auto_update 控制。提醒改变不触发下载，也不取消手动下载。关闭自动更新时取消在途自动获取，原子发布和保存错误路径保留。
- 自动安装要求候选 Ready、无错误、保存已结算、真实队列空闲，持续 30 秒且距最近应用交互至少 30 秒；用既有队列 revision 变化重置计时，避免漏掉两次轮询之间完成的短任务。候选验证后重新检查偏好、交互、revision 及原子接纳门。点击、键盘、指针及设置交互延后计时；手动安装不等待这段安静窗口，仍沿原任务及资源结算门。
- View.full_attention 只服务 Full，原 attention 的菜单栏语义保留。Full 使用已有 component_visible / update_attention 分支，方便 F 加入扩展类别，避免引入新提醒框架。
- Full 动作由当前阶段派生；Available 下载、Ready 请求重启、失败检查重试，处理中和已请求等待不可重复提交；点击时再读当前快照，避免陈旧闭包动作。
- 已就绪的更新仍可主动检查；相同已验证候选直接复用，不重新获取。检查失败后仅在原 pending 仍一致且可验证时保留 Ready，使用独立检查失败文案与正常安装动作，避免检查网络故障误报为安装失败。
- View.check_error 单独存放最近手动检查的安全错误码，仅关于页消费；update.error 保留安装及授权原因。相同候选重查不清除已有自动安装阻断，取消重查也不丢弃有效 Ready。旧快照缺少 check_error 按 None 读取。

## Risks / Trade-offs

- 旧版本保存的默认 idle_restart=false 无法区分显式选择 → 统一保守映射为关闭，在关于页明确显示；不删除原文件或其他配置。
- 持续操作会延后自动安装 → 手动入口随时可用，后台下载与检查照常。
- Gallery 只证明真实布局的合成展示 → 持久化、四组合及安装安全门另用定向 owner 测试，最终 UX 交用户验收；不声称完成真实公开更新安装。

## Migration Plan

读取时兼容旧字段，用户保存时原子写入新双字段；读取失败保留错误并禁止自动动作。整合者统一 sync/archive 本 change，其他 owner 冲突按约定最小差异整合。
