# Spec Delta

## MODIFIED Requirements

### Requirement: 单区间使用原生快速粗切

系统 SHALL 默认将有效单区间点播请求交同一下载器，以原生区间和关键帧附近流复制优先减少长源取数及等待。只有用户显式开启精确时 SHALL 使用原生区间重新编码，以源帧/采样边界处理选定时间，允许帧时长及封装的小量化误差，不承诺任意毫秒恰有视频帧。范围与模式在受理及重试中冻结，去重区分模式。不支持的引擎/直播/越界明确拒绝；范围失败不得静默完整下载再裁剪、交付整片或回退粗切。实际取数与边界偏差分别说明，不承诺所有格式只传片段。

#### Scenario: 非关键帧区间

- **WHEN** 用户提交非关键帧入点且未开启精确
- **THEN** 按原生快速区间流复制，保留计划codec及所选音轨，允许有界的关键帧附近偏差，不能将整片或明显截短输出判为成功。

#### Scenario: 长源短片段取数

- **WHEN** 验证首期支持的HTTP Range或分段流路径
- **THEN** 使用可计量长源记录服务器实际响应字节与完整源大小，确认只取部分；不能只凭退出码、时长或静态选流判断节省取数。

#### Scenario: 显式精确与真实校验

- **WHEN** 用户开启精确后提交非关键帧区间
- **THEN** 重新编码并核对所选音轨、冻结画质及成品时间；采用精确模式的帧/采样量化容差，不沿用粗切GOP宽容差；引擎或验证失败沿既有失败与诊断，不自动改为粗切。
