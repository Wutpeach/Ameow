# Design

## Context

现有桌面控制通过本机私有传输将命令交给同一桌面队列 owner；任务 ID 绑定随机实例，写入通过请求键关联，异步下载用快照和资源结算表达。组件更新和应用更新各有原业务 owner 和安全阶段，设置持久化也有现成校验。见 proposal 和对应规范增量。

## Goals / Non-Goals

**Goals:** 保留现有权威、权限和资源生命周期，暴露能让 Agent 区分受理、运行、完成、失败或失联的操作与状态；对旧实例按能力明确拒绝。

**Non-Goals:** 不引入第二套下载器、服务、账号接线、任意组件版本或额外输出策略；不借用生产签发资料进行 fixture 验证。

## Decisions

- 媒体查询成为正式队列任务，并用原有 show/wait/cancel、实例 ID 和可用能力协商；替代建立无关联的同步解析进程，保留取消及清理的权威。
- 持久偏好通过已有保存路径修改，提交选项仍只属于该任务。失败回执基于真实保存结果，避免 UI 与 Agent 的默认值分叉。
- 组件及本体维护由现有 owner 接受命令和输出各自状态，不根据队列命令排队成功推断操作成功。CLI 中断或连接丢失不替 owner 宣告任务结算。
- 显式请求重放保留同实例、同键和同内容的约束，能力不存在或旧实例不支持时拒绝，避免旧版本静默忽略新字段。

- 下载组件请求绑定业务 owner 返回的组件与代际；已观测结算保留在当前控制 owner 内，后续操作不能改变该结果；未观测结算而被替换时明确返回结果未知。
- 普通退出/重启在同一队列排空资源后交还原 UI 退出；既有 CLI 的一次性观察模式持有原进程身份，退出后重启正常入口并验证新 owner。安装和生命周期分别仅保存最近的小回执，用操作 ID 和原实例身份恢复查询，不新增下载持久历史。安装完成还须核对已接受的安装版本。
- CLI 偏好先占用原 UI 设置事务；快捷键沿原生 prepare / persist / complete，保存失败保留原注册。队列 revision 防止迟到 GUI 回执覆盖已确认的新值。

## Risks / Trade-offs

- [应用更新及退出导致原实例消失] → 将切换过程、失联及新实例事实分别表达，不凭失联推断完成。
- [组件检查/启用异步且各自可能失败] → 按组件保留阶段、目标及实际版本，复用既有诊断和更新安全门。
- [跨平台及真实签名测试环境不同] → 使用已有隔离 fixture 做定向验证，分别记录未覆盖的平台和生产链路。

## Migration Plan

CLI 和桌面应用使用匹配完整包；旧 owner 对未声明能力的请求明确拒绝。随候选交付更新帮助和双语文档，已发布文档在实际版本上线前保持版本边界；回退到旧完整包使用旧 CLI 契约。
