## MODIFIED Requirements

### Requirement: 下载器拥有提取和原生选流

系统 SHALL 通过中性 Adapter 传递意图、阶段、进度和产物；composition 选择实际引擎及可信工具需求。提取、支持性、格式选择、内部恢复、私有协议及错误解析由实际下载器负责；MUST NOT 用未知媒体字段、固定图库元数据形状、扩展名白名单或成功执行的警告重做能力判断。核心、队列和 GPUI MUST NOT 解析原始引擎 JSON、Format ID 或内部重试计数，也不得承担 metadata replay 或 load-info-json；Adapter 不重建候选排序或全体 CDN 等值预检。yt-dlp Adapter 内允许下述匿名同 attempt 的原生信息输入。yt-dlp 视频保留现行 MKV 合并/remux 与真实传输的 no-simulate；观察选项 MUST NOT 跳过下载。

#### Scenario: 原生下载器选择媒体

- **WHEN** 选择 Highest、Balanced 或 Saver
- **THEN** yt-dlp Adapter 将意图映射为原生选择器与现行高度优先/同高度 codec 排序；上限分别为不限、1080、480，源字段未知时继续传输，实际成品再核对冻结上限。

#### Scenario: 图库成功但存在警告或不同元数据形状

- **WHEN** 下载器成功执行并提供完整产物记录，存在 stderr 警告或可选字段未知
- **THEN** 继续按实际图片或视频核验，警告和可选观察不冒充原生失败；真实原生错误、产品范围和不安全路径仍分别报告。

## ADDED Requirements

### Requirement: 匿名同次执行复用当前原生解析

yt-dlp Adapter SHALL 在匿名同 attempt 内以经过完整有界解析和身份受理的当前信息文件作为原生传输输入，并持有可信输入身份及运行时租约；原生引擎仍按冻结意图选流。恢复 URL SHALL 绑定已核对的 canonical，临时地址失效仅沿同一受控引擎进程的一次原生重新提取恢复；MUST NOT 新增 Rust 重试循环、跨任务/重启缓存或跳过最终身份及媒体验证。认证执行继续既有纯内存原始 metadata 与 Jar 路径，不新增秘密输入文件。新增输入不适合既有捕获限额时沿原 URL 执行，不能因优化扩大限额。

#### Scenario: 健康匿名同次传输

- **WHEN** 本次匿名解析已完整且身份受理通过
- **THEN** 原生引擎消费当前受管输入进行传输，不例行再次提取网页；同任务最终作品身份、冻结画质/区间、真实媒体和资源结算仍须全部通过。

#### Scenario: 临时媒体地址失效

- **WHEN** 当前原生信息中的临时地址失效，原生引擎沿已绑定 canonical 重新提取
- **THEN** 保留同一 attempt、认证边界、路由、冻结意图及 owner；审核当前执行与一次恢复的全部有界原生选流记录，更新实际进度源；最终对象记录仍恰好一条，身份变化或不受支持的所有权协议不得发布成功。

#### Scenario: 认证与新的执行

- **WHEN** attempt 带认证，或用户提交新任务、显式重试、重启或执行只解析
- **THEN** 认证不把原始秘密 metadata 写入原生信息输入文件；新的执行重新解析并使用其独立 Jar/租约/工作区，不复用旧签名媒体地址或此前只解析结果。

#### Scenario: 输入变化或取消

- **WHEN** 当前输入文件受损、替换或执行被取消，或真实清理失败
- **THEN** 拒绝使用不一致输入或发布成功，沿既有失败/取消及 Held 显式清理路径结算；不从 marker、文件名或大小猜测复用成功。
