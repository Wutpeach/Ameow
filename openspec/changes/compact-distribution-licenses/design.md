# Design

## Context

见 proposal.md。已发布 0.5.2 的完整包消费者强制每个版本槽文件（除主程序）都有根镜像，因此直接删除根 licenses 会使真实旧消费者拒绝 0.5.3 更新。现有离线许可从完整工程 inventory 和官方标准库 HTML 生成，材料中存在大量相同许可段落。

## Goals / Non-Goals

**Goals:** 保留现有完整包契约，以组件映射和共用完整纯文本减少实际材料；原始文本、SHA256 和来源保留在仓库；生成器能验证重建后的法律文字顺序与原文一致。

**Non-Goals:** 不改变更新格式、原始 0.5.2 资产、系统安装或生产信任；不声称一次物料整理解决所有历史许可来源缺口。

## Decisions

- 保留根和版本槽镜像：旧消费者需要，升级兼容优先；不引入新格式或过渡发行。
- 完整正文在空白归一化后去重，所有非空白字符、文字顺序和不同版权保留。组件通过编号直接映射连续完整的许可正文，避免要求读者跨段落重组。保留准确的来源哈希。
- 标准库去掉 HTML 展示标签，保留全部归属文字和链接；每个 pre 许可块映射到同一正文池，来源 HTML 原字节留库。
- 发行仅复制实际离线许可和简短索引；完整机器 inventory、编译工具上下文、源码/格式来源及非随包工具 GPL 上下文留库。离线 About 读取同一精简材料。

## Risks / Trade-offs

- [来源中缺少准确原文] → 保留已知缺口，不发明版权或用模板补齐。
- [文本归一化丢失文字] → 逐条重建原始完整正文的非空白 token 并比较，未知 HTML 标签和缺失锚点拒绝生成。
- [根镜像仍重复] → 明确保留原因和剩余占用，不报告未实现的文件布局去重。
- [最终运行时版本尚未稳定] → 本组定向材料检查先完成，最终包占用与实际升级由整合者在 #98 稳定后统一验证。
