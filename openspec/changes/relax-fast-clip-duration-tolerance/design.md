# Design

## Context

见 proposal.md。共享 verifier 分别核对容器时长与完整解码时长；精确分支先返回，快切现有下界为请求减 250 毫秒，上界为请求加十秒，并另行拦截已知整源。

## Goals / Non-Goals

仅修正默认快切上界；保持媒体完整性、对象/范围记录、精确校验和原队列/发布权威。没有请求参数优化、选流变更、全片下载后备或新设置。

## Decisions

- 上界固定为请求加 10.5 秒：保留原十秒预卷支持范围，半秒作为音轨包、重排和封装的粗粒度余量，覆盖已知 19/59 毫秒偏差；不按总源长或请求比例扩张。维持十秒仍会误拒绝，扩大数秒或无限容忍缺少本轮依据。
- 不改变短 250 毫秒下界及整源保护。用户可感知的最大成品时长差为短 0.25 秒或长 10.5 秒；它不是逐端点定位精度或节省流量承诺。
- 普通单测使用已有 typed 实验时长证明缺陷；Windows 离线真实 verifier 使用自有小媒体，复用只读且按 manifest 核验的 FFmpeg/ffprobe，不复制 runtime 缓存，所有可写工作区在任务证据目录。

## Risks / Trade-offs

- [粗切可能包含额外内容] → 固定上限，不随源长放大，需更严格边界者显式开启精确。
- [同长度错误片段不能只靠时长发现] → 原对象身份和 section 记录检查保持；不把时长窗描述为内容定位证明。
- [本轮不重下公网样本] → 复用已留 typed 包/源时间戳/解码证据，并跑离线真实 verifier；Mac 与公网端到端不作新验收声明。
