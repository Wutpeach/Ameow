# Design

## Context

main a7ba5b43 已有共享桌面队列和当前用户限定控制传输，Rust Adapter 尚无认证输入。参见 proposal.md；研究报告中的文件导入主流程已被 #24 扩展授权决定替代。

## Goals / Non-Goals

**Goals:** 在现有 owner、运行时隔离和两阶段下载中加入可撤销的站点会话，不改变原生选流责任。

**Non-Goals:** 不恢复 Electron，不建立第二个下载队列或独立后台服务，不新增失败引导，不实现点选、热键或媒体兼容事项。

## Decisions

1. MV3 扩展采用可选 HTTP(S) host 权限及官方 cookies API。当前网页按公共后缀表确定站点，授权界面显示站点及子域；站点不是下载白名单。分区 Cookie 不展平，仅同步可由 Netscape 表达的非分区 Cookie 并显示限制。
2. 独立 Native Messaging 可执行文件只在浏览器通信时短暂运行。固定扩展 ID 与 allowed_origins；只处理有界版本化会话消息，不执行下载。共享会话模块在跨进程文件锁下保存加密快照，支持桌面离线。无需启动 GUI 或另建网络服务。
3. 每个安装来源、每个授权随机标识及单调消息序号；同步只能更新当前授权，用户明确替换携带已观察的当前授权标识。移除删除记录，旧 sync 无法重建。桌面与桥接共用存储协议，owner 检查有效授权并取消失效 attempt。
4. Windows DPAPI 当前用户加密；macOS 系统 Keychain 保存应用密钥，AEAD 加密存储；文件/临时目录只允许当前用户。新 attempt 从运行时同一数据域取快照，独立 Jar 贯穿两阶段与 fallback；后台 Cookie 刷新不改在途 Jar。
5. 凭据不进入业务 projection。认证下载不保存原始日志/JSON，yt-dlp 原生文件记录只输出身份与媒体安全字段；错误仍按原有安全分类。临时 Jar 随工作区真实结算清理，撤销不跳过现有 owner 的进程/文件释放门槛。
6. 设置在现有下载页提供简洁会话区，复用控件、语言和主题；安装动作注册当前包的桥接。扩展同时单独打包，普通产品包携带桥接及扩展，更新完整性清单覆盖新增资产。

## Risks / Trade-offs

- 浏览器事件不能覆盖设备关机 → 启动、变化和周期补同步，离线缓存只是最近会话，不声明服务端仍有效。
- 浏览器分区、IP/设备绑定及站点风控 → 明示同步能力边界，实际兼容性由原生下载器和真实样本验证。
- macOS 原生验证需要可用 Mac → 先交平台代码与静态检查，通过实际 Mac 工作流后才能宣称原生通过。
- 会员样本需用户本地授权 → 先完成安装入口和工程检查，再交来源协调；不读取日常 profile 或聊天凭据。
