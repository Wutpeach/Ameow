# On-demand runtime acquisition

Scope: pinned Windows x64 runtime acquisition and its versioned source references. This is not a license approval, a legal conclusion, or a claim that runtime notices/source obligations for redistribution are complete.

The complete application portable ZIP, also used as the Windows application-update payload from the unreleased 0.5.2 layout onward, does not contain yt-dlp.exe, deno.exe, ffmpeg.exe, ffprobe.exe, or gallery-dl.exe. At first use, Ameow obtains the baseline Windows x64 publisher releases below directly from their listed HTTPS release URLs, verifies the pinned hashes in the embedded manifest, and prepares them in the current user's managed application cache. The executables are separate downloaded tools, not files embedded in the package. This describes the delivery mechanism, not an exemption from applicable license obligations.

The authoritative machine-readable acquisition URLs, per-file hashes, archive hashes, probes, and exact versions are in assets/runtime-manifest.json, compiled into the application from src/download/runtime.rs. That manifest is part of the build-input evidence. A future package that copies any of these executables must receive a separate review of the exact binaries, notices, source materials, and delivery model before external distribution. This declaration does not make that review or approve public release.

- gallery-dl 1.32.21: GPL-2.0-only; official Windows standalone acquired from https://codeberg.org/mikf/gallery-dl/releases/tag/v1.32.21. Source/licenses: https://github.com/mikf/gallery-dl/tree/v1.32.21. The pinned SHA-256 was calculated from the downloaded official HTTPS asset; the downloaded executable also matched the release’s official SHA256SUMS (no detached signature verification). The standalone includes Python/dependencies and requires the Microsoft VC++ x86 redistributable. Ameow disables gallery-dl yt-dlp module delegation and uses its own separately managed yt-dlp executable for supported videos.

Historical C2 source review (2026-11-09, application commit 1f4b3f21d7e770d427d7bcec109cc647014ce6ff): the then-pinned gallery-dl 1.32.19 EXE was 22,627,366 bytes with SHA-256 4DDA3F14EFBC8A8E616AF1FC7E1E88D795995326B47692453E620117254DEC18, as recorded in that commit's runtime-manifest.json. Its GPLv2 text is at https://github.com/mikf/gallery-dl/tree/v1.32.19 . Deno's project MIT text does not replace the V8/other third-party terms of its binary. FFmpeg's n9.0.2 annotated tag resolves to source commit 946fcce07b6dcd0331c8cc609192aeff5e1924f8; the builder's exact enabled libraries and source correspondence remain part of any future binary redistribution review.

The application also supports an explicit managed yt-dlp upgrade to an official stable release. The table is the pinned baseline, not an exhaustive license inventory of every version a user may later select. Hash/signature/version verification of an upgrade does not establish that release's complete third-party/source compliance.

Public review must distinguish the application ZIP (Rust code, embedded fonts/icons and static dependencies), direct upstream downloads performed on the user's machine, and any future mirror/bundle of runtime executables. This note covers direct upstream acquisition, not a runtime mirror or bundle. Whether the launcher/subprocess integration and acquisition model impose further notice/source delivery requirements needs an assessment of the exact release and delivery model. A GPL context text or a link to a repository does not by itself fulfill all executable redistribution/source obligations. The [2026-11-09 source review](https://github.com/Wutpeach/Ameow/blob/eb61f7b30a0a3c98de13bda7fc2bb29122186868/docs/application-update-stage-c2.md) records the examined candidate and open notice/source questions; it does not establish the status of later releases.
