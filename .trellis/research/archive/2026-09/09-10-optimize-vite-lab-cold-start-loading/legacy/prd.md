# Optimize Vite Lab cold-start loading

## Goal

以最小改动消除 Vite Lab 首次打开时的长时间加载阻塞，让开发者尽快看到可交互的 Lab UI，并保持暖态刷新和并发开发进程稳定。

## Background

- 用户现场观察：Vite ready 仅 390 ms，但首次 `/lab.html` 请求阻塞约 26.8 秒，依赖优化器仍持续 bundling。
- 上述数字为用户提供的基线，本任务尚未独立复测；不能把 ready 耗时当作页面可用耗时。
- 该问题另建独立任务处理，避免混入已完成的 Lab 简化工作。
- 研究已确认 Lab 与普通开发服务目前解析到同一个默认缓存目录（`vite.lab.config.ts:17-33`、`vite.config.ts:6-35`）；现有 Lab 构建入口已限定初始依赖扫描，显式扫描配置主要用于固定约束。详见 `research/lab-cold-start.md`。

## Requirements

- R1：验证并采用 Lab 独立的 Vite `cacheDir`，避免 Lab 与其他 Vite 开发进程争用同一 `node_modules/.vite/deps`。必须检查实际启动路径及同时运行多个 Lab 进程的行为，不能仅凭目录名不同推断无争用。
- R2：将 Lab 依赖扫描入口限定为 `lab.html`。
- R3：Lab 开发服务默认打开 `/lab.html`，避免默认打开生产入口而激活其依赖图。
- R4：优先使用现有 Vite 配置和启动脚本完成最小修复；任何超出上述范围的改动须先给出复测依据。
- R5：以实际浏览器中首次可见且可交互的 UI、暖态刷新和并发进程日志验证效果；若开发启动方式或用户指导发生变化，同步更新相关文档站页面。

## Acceptance Criteria

- [x] 冷态启动：记录缓存状态、启动命令、Vite ready、首次 `/lab.html` 响应及首次可见且可交互 UI 的耗时，保存浏览器和服务端证据；与相同环境下的修复前数据比较，确认不再出现已报告的长时间阻塞。不得只以 ready 或 HTML 返回判定通过。（R1–R5）
- [x] 暖态刷新：保留缓存刷新 Lab，记录可见 UI 的耗时，确认页面正常且无持续依赖重打包造成的等待。（R2、R5）
- [x] 并发进程：Lab 与普通开发服务同时运行，并覆盖两个 Lab 实例；记录各自有效 cacheDir、启动命令及日志，确认访问和刷新正常，依赖缓存操作无 `EPERM`。（R1、R5）
- [x] 入口隔离：验证实际初始依赖扫描入口为 `lab.html`，默认浏览器打开 `/lab.html`，不因默认入口选择而激活生产入口图。（R2、R3）
- [x] 与改动相关的项目检查通过；报告包含环境、复现步骤、修复前后测量结果及证据路径。（R4、R5）

## Out of Scope

- Lab UI 重设计、生产入口架构重构、依赖升级、通用性能监控系统。
- 与本任务无关的现有工作区改动。

## Final Evidence and Status

- 用户已批准初版与端口隔离修订方案；最终配置另外通过实测依据排除九个非 Lab 输入目录的原生文件监听，符合 R4 的最小配置修复边界。根因、初版失败与测量修正过程见 `retrospective.md`。
- 最终独立审查 `evidence/final-check-report.md` 判定 PASS：适用于默认回环地址、正整数固定且互不相同的端口、`strictPort: true`。不宣称任意 host/API 覆盖、端口 0 或关闭 strictPort 的实例隔离。
- 匹配对照中，导航至可见预览 28.851 秒 → 1.138 秒，可交互 29.175 秒 → 1.301 秒；进程启动至可见预览 29.265 秒 → 1.487 秒。两次暖态可见时间为 0.209/0.076 秒，源码 CSS HMR 22 ms，正常同端口重启复用优化器元数据。
- 双 Lab 与普通 Vite＋Lab 均有真实重叠的优化器工作、实际 Lab 刷新和无缓存权限错误证据。九个排除目录与 97 个本地入口依赖不相交；源码、locales、public 和配置仍受监听。
- Windows 单次顺序对照，不是通用性能 SLO；可见里程碑是布局观察，不是精确首次合成帧。现有确切 React 样式警告单独记录；普通服务的纯浏览器检查不代表 Electron 桌面功能或其性能已修复。
- `lint`、`type-check`、针对性检查及进程/缓存清理自检通过。用户于 2026-09-11 批准提交与归档；源码与规范已提交为 `c8872ff4`，任务进入完成归档。
