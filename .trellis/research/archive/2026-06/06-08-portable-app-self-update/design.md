# Portable app self-update design

## Architecture

Use one update manifest and two Windows install strategies:

- Installed Windows build: keep the current installer strategy.
- Portable Windows build: download the release portable ZIP, verify it, then delegate directory replacement to an external helper.

The renderer should keep using `window.ameow.updater.check()` and `downloadAndInstall()` so the UI stays mostly unchanged. Electron main owns the runtime-shape detection, asset selection, download, verification, helper launch, quit, and recovery contract.

## Manifest Contract

Keep the existing stable field for compatibility:

```json
{
  "version": "0.3.1",
  "notes": "...",
  "pub_date": "2026-06-08T00:00:00Z",
  "platforms": {
    "windows-x86_64": {
      "url": "https://github.com/Wutpeach/Ameow/releases/download/v0.3.1/Ameow_0.3.1_windows_x64_installer.exe"
    }
  },
  "portable": {
    "windows-x86_64": {
      "url": "https://github.com/Wutpeach/Ameow/releases/download/v0.3.1/Ameow_0.3.1_windows_x64_portable.zip",
      "sha256": "<hex>",
      "rootDir": "Ameow_portable"
    }
  }
}
```

Rationale:

- Existing installer clients continue using `platforms["windows-x86_64"].url`.
- Portable metadata is additive and safe for older clients to ignore.
- SHA256 can be computed in CI from the uploaded portable artifact.
- `rootDir` lets the helper validate ZIP structure before touching the live directory.

## Runtime Shape Detection

The update controller should receive an install mode resolver from Electron main:

- `installed`: NSIS/install path; use installer strategy.
- `portable`: ZIP-unpacked path; use portable strategy.
- `unsupported`: return update info only if a safe install strategy exists, otherwise expose a manual fallback.

Recommended detection:

- Prefer an explicit portable marker generated by `scripts/package-portable.ps1`, for example `resources/ameow-portable.json` or a root-adjacent `.ameow-portable` marker copied into the ZIP.
- As a compatibility fallback, treat a packaged Windows app as portable when `process.execPath` lives under a directory named `Ameow_portable` and the app is not inside the common NSIS install locations.
- Do not infer portable mode from `app.isPackaged`; both installed and portable builds are packaged.

## Portable Update Flow

1. `checkForAppUpdate()` fetches the selected manifest as it does today.
2. If the current build is portable and the manifest has a valid portable entry, store a pending portable update.
3. `downloadAndInstallAppUpdate()` downloads the portable ZIP to a temp update directory.
4. Compute SHA256 while or after downloading and compare to manifest metadata.
5. Extract ZIP to a staging directory beside the live portable root, not under `%TEMP%`, so Windows replacement can use same-volume rename semantics even when the portable app is on `D:` or removable storage.
6. Validate that staging contains exactly the expected portable root and an `Ameow.exe`.
7. Copy or generate the updater helper into the temp update directory.
8. Launch helper with structured arguments: live root, staging root, backup root, executable path, current PID, expected version, log path.
9. Only after helper spawn succeeds, mark the app as quitting and quit. If helper spawn fails, return an error to the renderer and keep the app running.
10. Helper waits for current PID to exit, renames live root to backup, moves staging root to live root, starts the new `Ameow.exe`, and removes backup on success when possible.

## Helper Strategy

Use a small Node script compiled by `tsconfig.electron.json` and launched with the packaged Electron executable in a detached helper mode, or use a standalone PowerShell helper generated at runtime.

Recommended MVP: a standalone PowerShell helper generated into the temp update directory.

Why:

- It runs outside the live app directory.
- Windows has PowerShell available on supported target machines.
- It can wait for a PID, rename directories, expand/copy files, write logs, and launch the executable without needing extra binaries.
- It avoids relying on old app resources after quit.

Constraints:

- Target Windows PowerShell 5.1 syntax as the minimum. Do not use PowerShell 7-only operators or behavior.
- Arguments must be passed as individual `spawn` args, not shell-concatenated strings.
- Refuse to operate on roots like drive root, user profile root, `Program Files`, or any path that does not contain the expected portable marker.
- Before waiting on the passed PID, verify that any live process with that PID still points to the expected executable path; if the PID is gone, proceed, and if it points elsewhere, abort.
- Retry rename operations with bounded backoff to tolerate short-lived locks from app shutdown, antivirus scanning, or child process cleanup.
- Use rename-based replacement where possible: `live -> backup`, `staging -> live`.
- If `staging -> live` fails after backup succeeded, attempt `backup -> live`.
- Keep backups timestamped on unrecoverable failure.

## Data Flow

GitHub Release artifacts
-> release workflow computes portable SHA256
-> `latest.json` includes installer and portable metadata
-> Electron main checks selected manifest
-> update controller stores pending update with install strategy
-> renderer calls existing `downloadAndInstall()`
-> main downloads and validates selected asset
-> helper replaces portable directory after app exits
-> helper relaunches new executable

## Compatibility

- Existing stable/prerelease manifest selection remains unchanged.
- Existing installer update clients continue to work because the installer URL stays in the same field.
- Older clients ignore the new `portable` object.
- New portable clients should not try to use installer URL unless explicitly falling back to manual release/install behavior.
- Current spec wording that forbids portable self-update must be updated during implementation.

## Failure Modes

- Missing portable manifest entry: show update info but disable portable install, or surface manual update fallback.
- Invalid portable root or missing portable marker: abort before downloading the ZIP.
- SHA mismatch: abort before extraction or replacement.
- Bad ZIP structure: abort before replacement.
- Live directory not writable: abort before helper launch.
- Helper spawn failure: keep the app running and surface a retry/manual update error.
- App does not exit: helper times out, logs failure, leaves live directory untouched.
- Replacement failure before backup: live directory remains untouched.
- Replacement failure after backup: helper restores backup, or leaves backup and logs exact recovery instructions.

## Security And Safety

- Do not execute files from the downloaded ZIP before validation.
- Validate URL is HTTPS before download.
- Verify SHA256 from manifest.
- Operate only on a directory that contains the portable marker.
- Do not recursively delete a path unless it has passed marker and path-depth checks.
- Reject ZIP extraction roots that contain anything other than the expected single `rootDir` directory.
- Avoid storing update state in user config; updater/install state remains runtime-owned per existing spec.

## UI Boundary

Renderer can keep the current phases, but `AppUpdateInfo` may need additive metadata:

- `installMode: "installer" | "portable" | "manual"`
- optional `manualUrl`

MVP UI copy should communicate that portable update will restart and replace the current portable folder. The main update badge can remain the entry point; no settings page expansion is required.

## Validation

Unit-test the pure pieces:

- manifest parsing with installer-only, portable-only, and both entries
- install-mode strategy selection
- SHA256 validation
- portable path safety checks
- helper script/argument construction
- helper spawn failure behavior
- same-volume staging path selection
- PowerShell 5.1-compatible helper syntax review

Integration/manual checks:

- package portable ZIP
- run a copied older portable directory
- point manifest to a local/test release asset if practical
- test a portable copy on a non-`%TEMP%` drive when available
- verify update replaces the copied directory and relaunches
- verify a locked or non-writable directory fails without damage
