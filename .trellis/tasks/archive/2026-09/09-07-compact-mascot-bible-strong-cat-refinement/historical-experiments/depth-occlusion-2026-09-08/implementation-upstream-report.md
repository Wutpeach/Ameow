## Implemented contract

- `RenderAvatarOptions.occlusion` accepts opt-in `"depth-aware"`; omitted or `"none"` keeps the legacy result.
- `AvatarGeometry.nodeFragments` is present only in depth-aware mode and contains one input-ordered `{ nodeId, backPath, frontPath }` record per body node. The legacy complete-node arrays remain intact for both legacy and depth-aware callers.
- Fragments reuse the 17x49 node grid, local and head transforms, projection, and existing path formatter. They compare sample depth against an analytic ray/ellipsoid depth query for sphere/mickey primaries and a deterministic 25x73 ray/triangle primary-surface fallback for other supported surfaces; ties stay behind the primary surface.
- `renderAvatarExpression`, `renderAvatarDefinition`, and `renderAvatarFrame` each accept only a trailing occlusion-policy pass-through.

The review fixed three safe local defects in the contribution:

- Outside-primary samples previously used `Number.MAX_SAFE_INTEGER` as their synthetic front depth. Crossing interpolation therefore landed near the inside endpoint and could paint most of a silhouette-straddling, physically-behind triangle in front of the primary. The sentinel is now the smallest fixed value above the behind-winning epsilon, so the split stays at the outside/head boundary instead of leaking across the head.
- Latitude-pole and clipped seam cells emitted zero-area closed SVG subpaths. Fragment assembly now drops polygons below the fixed internal area floor before formatting.
- The crossing fixture's explicit `BodyNode[]` annotation widened its known cone surface to unsupported definition-only surface variants, causing the root TypeScript check to fail. `satisfies BodyNode[]` now validates the fixture without discarding its concrete cone type.

The same focused test now also covers explicit `"none"` equivalence, an empty depth-aware node list, orthographic projection, rotated ellipsoid camera-depth sign, and non-degenerate formatted fragment subpaths. The algorithm review confirmed fixed-diagonal cell triangulation, input-order fragment ids, behind-winning ties, unchanged compatibility arrays, analytic sphere/ellipsoid rays, deterministic generic mesh fallback, wrapper pass-through, and regenerated standalone output; it found no dependency, definition-schema, renderer, canvas, clip-path, or mask addition.

## Remaining review gates

- The intended triangle-subpath representation is materially larger than legacy convex-hull output. A local diagnostic for two crossing cones measured about `125,729` fragment-path characters and `4.24 ms` per analytic-sphere render versus `5,984` characters and `0.94 ms` for legacy output; actual 56px browser/DOM measurement remains required before Ameow consumption.
- The deterministic generic cube-mesh fallback measured about `143.9 ms` per render in the same diagnostic. It is functionally correct and outside the Compact sphere path, but upstream should either accept/document that cost or optimize it before advertising depth-aware animation for generic primaries; this review did not add an unapproved spatial index or cache.
- The Windows package-smoke launcher limitation above remains outside this patch. Run that smoke on a host where the script can spawn pnpm, or repair the upstream script in a separate cross-platform tooling change.
