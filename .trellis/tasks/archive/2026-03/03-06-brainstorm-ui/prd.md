# Brainstorm: 批量下载 UI 与多任务标记设计

## Goal

在当前 `200x200` 的悬浮主界面内，设计一套可落地的批量下载交互：用户可连续加入多个下载任务；当存在多任务时，主界面显示数字标记 `X` 表示当前下载任务总数，并保持现有下载进度体验简洁稳定。

## What I already know

- 用户明确提出两个目标：
  - 设计批量下载功能（UI 界面）
  - 下载中新增任务时显示标记 `X`，`X` 为当前下载任务数；无多任务时不显示标记
- 当前主界面是单任务状态模型：`src/App.tsx` 使用单个 `downloadProgress` / `downloadStage`。
- 当前前后端下载事件契约不含任务标识：`video-download-progress` 和 `video-download-complete` 仅描述“当前下载”。
- 当前 Rust 侧是全局单下载进程语义：`src-tauri/src/lib.rs` 使用 `DOWNLOAD_CHILD`、`DOWNLOAD_CANCELLED` 全局状态。
- 主界面空间受限（固定约 `200x200`），顶部右侧已有关闭按钮，UI 叠加空间很紧张。

## Assumptions (temporary)

- MVP 先采用“单活跃下载 + FIFO 等待队列”，而非多并发下载。
- 标记 `X` 代表“活跃任务 + 等待任务”的总数。
- 任务来源统一视为同一队列（拖拽、粘贴、扩展触发）。

## Requirements (evolving)

- 支持连续加入多个下载任务；当已有任务执行中时，新任务进入等待队列。
- 当总任务数 `> 1` 时显示数字标记 `X`；当总任务数 `<= 1` 时不显示标记。
- 标记数在入队、完成、失败、取消后实时更新。
- 当前下载中的主视觉仍保持现有进度环与状态文案，不因队列引入大面积改版。
- 新增标记不应遮挡现有关键控件（关闭按钮、取消下载按钮）且保持深浅主题可读。
- MVP 采用“仅数字标记”方案：不提供等待任务列表弹层、不新增独立任务面板。
- 当用户点击取消时，仅取消当前活跃任务，并自动开始队列下一项（若存在）。
- `X` 仅统计视频下载任务（调用 `download_video` 的任务）；图片下载/文件复制不计入 `X`。
- 当前活跃视频任务失败时，自动继续队列下一项（若存在）。

## Acceptance Criteria (evolving)

- [ ] 只有 1 个任务（仅当前执行任务）时，不显示数字标记。
- [ ] 执行中 1 个 + 等待中 2 个时，主界面显示标记 `3`。
- [ ] 任一任务完成/失败/取消后，标记数按剩余总任务数正确递减。
- [ ] 队列清空后，标记自动隐藏，界面恢复默认状态。
- [ ] 标记在黑/白主题下都可清晰辨认，且不与现有按钮发生点击冲突。
- [ ] 执行中任务被取消后，若队列仍有等待项，下一项自动开始下载。
- [ ] 连续执行“视频 + 图片 + 视频”时，`X` 仅反映视频队列数量，不受图片任务影响。
- [ ] 执行中任务失败后，若队列仍有等待项，下一项自动开始下载。

## Definition of Done (team quality bar)

- Tests added/updated (unit/integration where appropriate)
- Lint / typecheck / CI green
- Docs/notes updated if behavior changes
- Rollout/rollback considered if risky

## Out of Scope (explicit)

- 真并发多路下载（同时下载 2+ 个任务）。
- 完整下载任务中心（筛选、排序、历史归档、重试策略配置）。
- 本轮不重构整套下载协议为复杂事件流（仅满足 MVP 所需最小扩展）。

## Technical Notes

- 关键现状文件：
  - `src/App.tsx`：当前单任务进度 UI、下载事件监听、取消下载按钮
  - `src/contexts/ThemeContext.tsx`：当前主题色定义（暂无任务标记专用色）
  - `src-tauri/src/lib.rs`：下载命令与取消命令、全局下载进程状态
  - `.trellis/spec/frontend/type-safety.md` / `.trellis/spec/backend/type-safety.md`：现有事件契约
- 当前约束：
  - 事件 payload 没有 `taskId`，不利于精细化多任务进度跟踪。
  - 后端取消语义是“全局取消当前下载”，需与队列策略保持一致。

## Research Notes

### What similar tools do

- 常见下载器/浏览器模式：主入口显示“任务数量摘要”，详情列表在次级面板展示。
- 小尺寸浮窗通常采用“数字标记 + 最小反馈”，避免主界面被任务列表挤占。
- 批量下载 MVP 常先落地“串行队列”，并发能力后置。

### Constraints from our repo/project

- 现有主界面交互密度已高，新增 UI 必须非常克制。
- 当前下载生命周期事件仅适配单任务语义，多任务需要最小协议扩展或前端队列抽象层。
- 取消能力目前偏“全局”，要避免和“队列中等待任务”概念冲突。
- 现有进度事件命名与契约均为视频下载语义（`video-download-progress` / `video-download-complete`），与“`X` 只统计视频任务”天然一致。

### Feasible approaches here

**Approach A: 仅数字标记（已选）**

- How it works:
  - 主界面新增任务计数标记 `X`（仅 `>1` 时显示）。
  - 维持当前中心进度环只代表“当前活跃任务”。
- Pros:
  - 改动最小、风险最低、最适合 `200x200` 窗口。
- Cons:
  - 用户无法直接看到等待任务明细。

**Approach B: 数字标记 + 极简队列弹层**

- How it works:
  - 保留标记；点击或悬停标记显示最多 3 条等待任务摘要。
- Pros:
  - 比 A 更透明，用户能确认“排队是否成功”。
- Cons:
  - 交互复杂度与遮挡风险上升。

**Approach C: 独立任务面板（设置页/新窗口）**

- How it works:
  - 主界面只显示计数，详情迁移到专门任务页。
- Pros:
  - 可扩展能力最强（重试、优先级、历史）。
- Cons:
  - 偏重型方案，不适合作为当前 MVP。

## Expansion Sweep (Diverge -> Converge)

### Future evolution

- 后续可扩展为“可暂停/重试/调序”的完整任务队列中心。
- 后续可细化为按来源分组（拖拽、粘贴、扩展）统计。

### Related scenarios

- 主界面取消按钮语义与队列语义统一为“取消当前并继续下一项”。
- 与现有“完成后短暂成功/失败反馈”动画保持一致，不引发状态闪烁。

### Failure & edge cases

- 快速连续加入 10+ 任务时，计数更新必须稳定且不丢失。
- 当前任务失败时，队列自动拉起下一项，同时保留失败反馈日志。
- 应用重启后队列是否恢复（建议 MVP 不恢复，直接清空）。

### Converged MVP Boundary (draft)

- MVP 优先落地：串行队列 + 数字标记 + 活跃任务进度展示。
- 取消语义固定为“取消当前并自动继续下一项”。
- 失败语义固定为“当前失败并自动继续下一项”。
- `X` 计数范围固定为视频下载任务，不扩展到图片/文件任务。
- 队列详情展示、任务历史、并发下载延后到后续迭代。

## Decision (ADR-lite)

**Context**: 主界面尺寸固定且交互密集，需要在不打断现有下载体验前提下支持多任务下载可见性。  
**Decision**: 选择 Approach A（仅数字标记），MVP 不引入队列详情 UI；取消与失败均采用“结束当前并自动继续下一项”。  
**Consequences**: 交互学习成本和改动风险最低；但等待队列透明度有限，后续可再加轻量详情弹层。

## Technical Approach

- 前端在 `src/App.tsx` 引入视频任务队列状态（`active + pending`），统一由单入口调度器串行执行 `download_video`。
- `X` 标记展示位置采用主界面右上角小圆角徽标（避开关闭按钮点击区），仅当视频任务总数 `>1` 显示。
- 进度环继续绑定当前活跃任务；队列中的等待项不单独渲染详情。
- 完成/取消/失败都触发统一“拉起下一项”逻辑，保证批量任务不中断。
- 图片下载与文件复制维持现状，不进入视频队列、不参与 `X` 计数。

## Implementation Plan (small PRs)

- PR1: 前端新增视频队列调度层（入队/出队/串行执行/自动续跑），保持现有单任务 UI 可用。
- PR2: 主界面加入 `X` 徽标与计数更新逻辑，补充主题色与点击区域防冲突处理。
- PR3: 回归验证取消/失败自动续跑与混合任务计数边界，补充文档与类型契约说明。
