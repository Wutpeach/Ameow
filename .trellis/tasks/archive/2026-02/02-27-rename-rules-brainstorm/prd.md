# Rename 功能增强（Brainstorm）

## Goal

修复重命名计数默认方向与起始值的行为错误，并设计一套「对新手友好、操作简单」的重命名规则自定义能力，让用户在设置界面可直观配置、低学习成本地完成批量重命名。

## What I already know

- 当前重命名功能在开启后默认是从 `1` 开始递增。
- 期望行为是默认从 `99` 开始递减。
- 用户希望新增「自定义重命名规则」能力。
- 用户明确要求：规则配置不能复杂，适合代码小白；UI 也必须简洁。
- 现有设置页仅有 `Enable Rename on Download` 开关，没有重命名规则参数输入。
- 主窗口当前已有“重命名计数重置按钮”，点击会清空后端重命名计数状态。

## Assumptions (temporary)

- 当前存在一个设置界面，且已有重命名相关开关或参数。
- 重命名执行流程已支持“数字序号命名”，但默认值/方向在不同路径存在不一致实现。
- 新增规则可在不引入脚本表达式/正则编辑器的前提下满足大部分需求。

## Requirements (evolving)

- 修复默认行为：开启重命名后，默认从 `99` 开始按 `-1` 递减。
- 在设置界面提供简单、低门槛的重命名规则配置入口。
- 规则配置与默认行为要可预期，避免用户误操作。
- 与现有开关、重置按钮、下载路径（视频/图片/扩展截图）保持一致语义。
- MVP 方向采用“可见提升”：必须包含预设选择 + 即时命名预览。
- 预设集合已确认其中 3 个方向：
  - 纯数字倒序（默认）
  - 纯数字正序
  - 前缀 + 序号
- 采用“3 个预设 + 通用后缀输入框”方案，不新增第 4 个独立预设项。
- 后缀能力通过单独输入框提供，以降低下拉选项复杂度并提升可复用性。
- 后缀输入框为全局生效，可与 3 个预设组合。
- 预览区采用“1 条示例”样式，优先保证简洁。
- MVP 不开放“起始值/步长”高级设置，先固定为预设内置值。
- “前缀 + 序号 + 后缀”默认自动使用下划线 `_` 作为连接符（如 `Flow_99_done.mp4`）。
- 当前缀/后缀包含非法字符时采用自动清洗策略（替换为 `_`），不中断保存流程。
- 重命名开关关闭时，规则配置区直接隐藏，保持设置界面简洁。

## Acceptance Criteria (evolving)

- [ ] 新安装或首次使用场景下，重命名默认参数为 `start=99`、`step=-1`，且首次命名优先给 `99`。
- [ ] 用户可在设置界面完成至少一类规则自定义，且无须编写代码。
- [ ] 规则配置流程不超过 3 步即可完成保存。
- [ ] UI 文案能让新手理解每个选项用途。
- [ ] 开启/关闭重命名与重置计数器的行为不冲突，且可解释。
- [ ] 设置界面可展示“下一条文件名示例预览”，且会随预设/参数变化实时更新。
- [ ] “前缀 + 序号”预设可用，且预览文案清楚展示前缀效果。
- [ ] 设置页提供后缀输入框，用户无需代码即可附加后缀。
- [ ] 同一后缀能力可与 3 个预设组合并正确预览结果。
- [ ] 设置页预览区仅展示 1 条示例文件名，避免界面拥挤。
- [ ] MVP 设置页不出现“起始值/步长”输入控件，避免新手负担。
- [ ] 前缀/序号/后缀拼接结果默认使用 `_` 连接，且预览与实际命名一致。
- [ ] 前缀/后缀含非法字符时会被自动清洗，且预览结果与最终落盘文件名一致。
- [ ] 关闭重命名开关后，规则配置区不显示；开启后显示并恢复上次配置。

## Research Notes

### What similar tools do

- 轻量方案常见做法是“预设优先”，而不是让用户直接写表达式。
- 高级批量重命名工具通常功能很强但学习成本高，不适合本项目“新手友好”目标。
- 对新手更有效的是“即时预览 + 2~3 个常用选项（起始值/方向/前后缀）”。

### Constraints from our repo/project

- 设置窗口尺寸较小，且当前交互是 toggle + 按钮风格，不适合塞入复杂规则编辑器。
- 后端已有计数器重置机制，适合继续采用“计数驱动命名”思路而非推翻重做。
- 现有下载链路较多，MVP 应该尽量只引入少量新配置键，降低回归风险。

### Feasible approaches here

**Approach A: 预设模式 + 简化高级项**（Recommended）

- How it works:
  - 默认预设：`99 -> 1`（修复 bug）。
  - 设置页增加“命名规则”下拉：`倒序数字` / `正序数字` / `前缀+序号`。
  - 增加通用“后缀”输入框（替代“序号+后缀”独立预设）。
  - 仅在“自定义”或“高级”折叠中暴露 `起始值` 与 `步长` 两项。
- Pros:
  - 学习成本最低，符合小白定位。
  - UI 改动小，适配小窗口。
  - 便于后续扩展更多预设。
- Cons:
  - 规则自由度有限，重度用户可能不满足。

**Approach B: 可视化规则拼装（Token Chips）**

- How it works:
  - 用户从 3~4 个片段中勾选顺序（如：前缀、序号、原名、后缀），系统拼装结果并实时预览。
- Pros:
  - 比预设更灵活，仍不要求写代码。
  - 可视化程度高，易理解。
- Cons:
  - 实现复杂度和状态管理明显上升。
  - 在 `320x400` 设置窗内容易显拥挤。

**Approach C: 仅修 bug + 单一扩展项**

- How it works:
  - 先只修复默认 `99 -> 1`。
  - 新增 1 个扩展项：`添加前缀` 或 `添加后缀`（二选一）。
- Pros:
  - 交付最快，风险最低。
  - 几乎不会增加 UI 复杂度。
- Cons:
  - 创新不足，用户感知提升较小。

## Decision (ADR-lite)

**Context**: 需要在“新手友好 + 简洁 UI”下增强重命名能力，并尽快让用户感知价值。  
**Decision**: 选择“可见提升”路线，MVP 采用预设规则 + 即时预览，不走仅修 bug 的最小改动方案。  
**Consequences**: 前端设置页会增加少量配置控件，后端需统一重命名默认计数逻辑；复杂规则编辑器继续排除在 MVP 之外。

## Technical Approach

- 配置层新增（或明确）重命名规则键：
  - `renameRulePreset`: `desc_number` | `asc_number` | `prefix_number`
  - `renamePrefix`: string
  - `renameSuffix`: string
- 后端统一序号策略：
  - 修复 `rename` 路径默认为 `99 -> 1`，与既有倒序分配一致。
  - 规则拼接格式：`<prefix>_<number>_<suffix>`（空段自动忽略多余 `_`）。
  - 前后缀非法字符统一清洗为 `_`。
- 前端设置页（小窗友好）：
  - 保留主开关 `Enable Rename on Download`。
  - 开启时显示：预设下拉 + 前缀输入 + 后缀输入 + 单行实时预览。
  - 关闭时隐藏整块规则配置区。

## Expansion Sweep (Diverge)

### Future evolution

- 后续可扩展“按文件类型”差异化规则（视频/图片）。
- 后续可扩展“站点级预设”但保持默认全局规则优先。

### Related scenarios

- 与主窗口“重置计数器”语义一致：重置后预览应立即反映基线变化。
- 与重命名总开关联动：关闭时隐藏规则配置，防止误解。

### Failure & edge cases

- 前缀/后缀为空、仅空格、包含非法文件名字符时应自动清洗并提示。
- 序号冲突、序号耗尽、写配置失败时应给出明确错误，不影响下载进程稳定性。
