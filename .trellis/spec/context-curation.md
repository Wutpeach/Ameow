# 上下文整理规则

## Spec

Rust / GPUI Next 是正常开发上下文；Electron 文档保留为冻结参考，除非获准工作需要。索引负责导航，不重复完整契约；只有内容具有独立适用范围时才拆分，不按文件长度机械拆分。保留来源、范围、例外、替代关系和未验证边界。

Linear 管理批准的产品范围和交接；仓库代码、测试与实际运行证据只证明其各自覆盖的实现事实。Research 保存历史调查，旧报告和归档任务指令不授权新的产品工作。

## Research 与保留

按索引、相关主题摘要、原始证据或 `legacy/` 的层次逐级查阅。最近 30 天只是发现优先级，不是自动加载或删除规则；所有更早历史与重要 Rust 架构决策继续保留，Electron 历史作为冻结参考。保留发布包、验收可执行文件、运行时、源码快照、日志和原始报告；只有明确获准且可重建的缓存才可以清理。

两个工作区的历史树不同，相关证据可能分布在两处时应分别查询；外部迁移保护副本用于恢复与审计，不是默认启动上下文。保留历史报告原貌，不悄悄改写原意。

## Cindy 会话历史

mini-trellis 0.3.1 的 Codex 历史检索读取用户目录下的 `.codex/sessions`；Cindy 可以使用另一处 `CODEX_HOME`。因此，mini-trellis 返回空结果或提示检索不完整，不足以证明相关会话不存在，也不能证明它已检索 Cindy 的全部会话。

当确需查找先前讨论且 mini-trellis 结果不足时，可在已有权限范围内使用 Cindy 的 `search_chat_history` 搜索对应工作区，必要时用 `get_chat_history` 查看相关原文。两处工作区按需分别搜索，不按最近 30 天截断历史。Cindy 检索和 mini-trellis 检索的来源与覆盖范围不同，应保留来源并检查结果是否完整，不把其中一方的无结果当成全部历史的结论。

## 维护

- 只在确认了持久知识或明确要求交接时更新 Spec、Research 或 Journal，不要求每次代码修改都写入。
- 区分实测事实、已批准决定、推断和未解决问题。
- 不重建强制 Trellis Task 或阶段流程；mini-trellis 管理知识，不代替 Linear 任务生命周期。
- 保留来源；只有来源和唯一目标得到确认才修复旧引用，无法确定时记录原因而不猜测。
- 验证受影响链接；不修改 mini-trellis 托管脚本、模板或内置 Skill。
